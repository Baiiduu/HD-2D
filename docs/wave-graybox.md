## 试玩

2026年10月13日最新：自动攻击已替换为 [A01 扇击](fan-auto-attack.md)，参数在 `WavePrototype / FanAutoAttack` 调节，默认伤害 10、扇长 2.4 米、扇角 100°、间隔 0.8 秒；独立播放 Meowa 斩光，人物沿用现有动画。波次入口已随新战场移到 `(0, 0, 25.6)`；地图位置以 [南侧战斗区域](battle-area-plan.md) 为准。下方早期灰盒截图与 6.4 米单目标攻击参数保留作历史参考。

在 Godot 的地图切换工具运行“正式连续地图”，或打开 `demoWithMeowa/1/scenes/world/world.tscn` 后按 F6。F5 的默认入口仍是视觉测试地图。

从小院沿南侧道路走到新战场入口，靠近灰色圆点 `(0, 0, 25.6)` 后按 **F** 开始。人物保持原有 WASD 移动、空格跳跃、Shift 瞬移和 QE 旋转。

- A01 自动选择范围内、无遮挡的最近史莱姆来确定方向，扫击前方扇区，可命中多只怪物；独立斩击特效由 Meowa 提供，人物保持现有动画。命中时怪物短暂变亮；测试基线为 20 生命、每次伤害 10，即两次命中击杀。
- 复用现有蓝色史莱姆的外观、八方向动画、受光与遮挡轮廓。分批出现，缩小显示 0.8 秒作为现有灰盒预告；预告期间不移动、攻击或受伤，然后沿可达路线持续追击。
- 接触造成真实血量损失，检查距离、高差与墙体遮挡；多个敌人及以后接入的弹丸、危险区共用受击保护间隔。
- 清空本波后直接进入休整，停止刷怪；不倒计时、不自动回血，也不提供技能或成长奖励。按 **F** 或“开始下一波”继续。
- 休整可按 **Tab** 查看背包。技能页保留说明占位，左下技能槽为空；战斗期间不打开会占用移动的管理页。
- 最后一波清空后结算。生命耗尽或离开南侧战斗范围也会结束本轮；结果页可以重试，或返回小院。休整时也可主动撤退。

波次参照 [战斗核心设计](combat-core-design.md) 的持续追击、生成预告、统一受击保护与安全清波约定。本轮接入史莱姆和后续怪物接口，未接入其他怪物招式、十种人物攻击、增益选择或永久解锁。

地图原有的单只 `Slime` 在挑战开始后隐藏并停止活动，返回小院时恢复巡逻展示，避免与波次敌人混淆。现有装备、训练、种植和学习存档不因挑战而改写，挑战本身不保存成长进度。

## 可调参数

选择正式地图的 **WavePrototype**。以下均为测试基线，数值不是最终玩法方案。

| 参数 | 默认 | 用途 |
| --- | --- | --- |
| `show_ui` | 正式地图关闭 | 显示或隐藏挑战界面，支持运行时切换；不影响人物属性条、技能栏和背包 |
| `default_enemy` | `data/wave_slime.tres` | 默认怪物场景与基础数值；替换资源即可选择其他怪物 |
| `waves` | 空 | 留空使用下面的递增配置；填入 `WaveDefinition` 后按资源数组运行，每波可混合不同类型 |
| `total_waves` | 3 | 递增模式的总波数；显式配置 `waves` 时使用其数组长度 |
| `first_wave_enemies` / `enemies_per_wave` | 5 / 2 | 首波数量与每波增加的数量 |
| `spawn_interval` / `spawn_warning` | 1.3 / 0.8 秒 | 分批生成的间隔与出现前预告时间 |
| `spawn_safe_distance` | 5 米 | 生成点避开人物当前位置；不满足时另选可达地点 |
| `max_active_enemies` | 30 | 同屏上限，包含出场预告中的敌人；满时延后生成，不丢弃队列 |
| `unreachable_timeout` | 10 秒 | 残怪持续无法到达或跌落时明确中断挑战，可重试，不伪造清波 |
| `hurt_interval` | 0.7 秒 | 所有敌方伤害来源共享的受击保护时间 |
| `FanAutoAttack.damage` / `attack_interval` / `attack_range` | 10 / 0.8 秒 / 2.4 米 | 当前自动扇击参数，在武器子节点调节；扇角及表现见 [A01 说明](fan-auto-attack.md) |
| `battle_area` | 新战场 `Rect2(-24, 20.8, 48, 48)` | 战斗的世界 XZ 范围，由 BattleArea 同步 |
| `interaction_radius` / `interact_key` | 2.5 米 / F | 开始挑战的距离与交互键 |
| `random_seed` | 12102026 | 生成位置的随机种子，重启生效 |

每轮开始与返回小院时恢复生命，波间保留当前血量。生命上限继续来自角色真实属性；基础攻击使用上表参数，尚未接入装备攻击、防御、蓝量消耗或掉落经济。

展开 `default_enemy` 或打开 `data/wave_slime.tres`，可调 `health`（20）、`move_speed`（1.35 米/秒）、`attack_damage`（8）。这些数值传给具体怪物，不替它判断命中。史莱姆场景的 `Combat Stop Distance`（0.65 米）、`Contact Distance`（0.85 米）、`Contact Height`（0.8 米）、`Warning Scale`（0.35）和 `Hit Flash Seconds`（0.15 秒）独立可调；接触距离应大于停止距离。

## 后续怪物与波次接口

- `WaveEnemyDefinition`：指定可复用怪物场景、显示名、生命、移速和攻击伤害。怪物场景根节点继承 `WaveEnemy`，美术与招式保留在各自场景和脚本中。
- `WaveSpawnEntry`：一组怪物的资源、数量、相对本波开始的首次生成时间及生成间隔。
- `WaveDefinition`：一波的生成条目数组与威胁说明。休整界面开启时显示下一波说明；正式地图仍沿用隐藏灰盒界面的设置。

新增怪物实现 `_combat_tick(delta)` 中自己的追击、冲锋、远程或区域逻辑。命中成立后调用 `damage_player.call(amount)`；返回 `true` 才代表本次实际受击，可据此触发受击效果。重写 `configure_wave`、`_ready` 或 `_physics_process` 时须调用父类对应方法。公共基类只处理配置、出场等待、受伤、一次死亡通知和取消，不规定接触攻击。

敌方弹丸与危险区放在 `attack_root` 下，清波、失败、撤退和返回流程统一清理。所有回调绑定当前波次代号，旧波次的伤害和生成请求不能污染休整或重试。

分裂或召唤在 `_on_defeated()` 等同步事件里，先调用 `request_spawn.call(definition, count, delay, world_position)` 登记，再延迟出现。位置使用 `Vector3.INF` 表示随机可达地点；指定地点也会检查可达性与安全距离。登记后即计入待生成数量，母体死亡不提前清波。实际分裂怪与召唤招式尚未接入；代数、召唤总数等由对应怪物限制。

清波条件为 **场上敌人归零且待生成队列归零**。出场预告中的实例也计入场上数量；两者归零后，先移除敌方攻击对象，再进入无限时休整或结算。地形碰撞重建后共享导航自动刷新；残怪意外移除或持续不可达会明确中断，可重试。

## 实现与验证

可复用组件：`scenes/shared/wave_prototype.tscn`。波次控制器、怪物公共接口、配置资源类型与临时界面位于 `scripts/combat/`，史莱姆招式位于 `scripts/enemies/slime.gd`。技能与成长的早期尝试已经从当前代码撤下。

`tests/test_wave_prototype.gd` 检查 F 开始、最近目标的基础攻击、墙体遮挡、QE 不改变目标逻辑、真实血量与受击间隔、失败重试、三波清波／休整／胜利、无限时安全休整、技能页占位、空技能栏、原存档状态保持、越界结束和主动撤退。

`tests/test_wave_core.gd` 检查真实史莱姆、两次命中击杀、安全生成与预告、待生成清波条件、同屏上限、混合怪物配置、不同攻击策略、共享受击保护、母体死亡后的延迟幼体、安全休整清理、旧回调失效、真实追击、地形重建、接触遮挡与高差、不可达中断以及无效怪物场景。测试替身仅验证接口，不作为新怪物加入游戏。原展示史莱姆的 `tests/test_slime.gd` 47 项检查继续通过。

原灰盒的 D3D12 / Forward+ 验证覆盖基础自动攻击、清波休整、Tab 占位页、失败、重试与返回按钮。

2026年10月13日，在 D3D12 / Forward+ 下让默认三波 5／7／9 只史莱姆实际生成、寻路、被基础自动攻击击杀，累计 21 只，完成两次安全休整、胜利结算与返回。另行隔离四只实例核对出场预告、追击动画与遮挡轮廓。逻辑测试和实机验证均通过；所有生命、伤害和密度仍是测试基线。

后续讨论技能获得、实际施放和成长时，在这个波次基础上逐步接入。
