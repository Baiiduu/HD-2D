# Meowa 音效制作与接入指南

用于后续会话制作、修改和接入本项目音效。先核对当前正式画面、动作事件和已确认音源，再决定是否需要生成。当前音效选择与播放实现见[人物动作与战斗声音](movement-audio.md)，音乐衔接另见[BGM 与曲池](background-music.md)。

**制作顺序：提取画面与动作特征 → 确定声音方向 → 提交完整提示词与本次数量、参数、预计积分 → 用户确认后生成 → 单条与动作连续试听 → 用户认可后接入 → 正式战斗人工验收。** 提示词确认、试听认可和正式接入是不同的授权；已有明确授权继续执行，不重复询问。

## 先从实际画面确定声音

当前主要体验是夜间 HD-2D 战斗中的蓄力、人物高速弹射、接群环绕和密集命中，声音需要与雨声、BGM、怪物动作同时存在。不能只凭“像素游戏”“有力量感”或“卡通”几个词生成。

制作前读取对应场景、动作资源和声音配置，明确以下内容：

| 要确定的内容 | 本项目中需要区分的情况 |
| --- | --- |
| 真正发声的主体 | 人物身体、聚拢气流、雷片、怪物身体、道具材质或界面 |
| 动作阶段与触发点 | 开始蓄力、持续蓄力、首次满蓄、松手发射、真实命中、致死或尸体演出 |
| 画面运动与力量变化 | 向内聚拢、瞬间释放、撞击后回弹、沿怪群连续传播 |
| 播放方式与密度 | 单次、可中断循环、按片合并、连续多次触发 |
| 声音层级 | 主确认声、轻材质层、持续气流、环境伴随声 |
| 应复用的基准 | 用户已经认可的音源、同类事件的响度和现有循环 |

方向有歧义时先问具体问题。例如“没有力量感”可能是主体音色不对，也可能是起声太晚或被混音压住；“听起来空”需区分几乎听不到与听得到但缺少打击感。先查波形和播放链路，再决定调整音量、剪辑或重新生成。

## 这几轮必须记住的经验

| 已遇到的问题 | 后续处理原则 |
| --- | --- |
| 素材前面有静音或很弱的铺垫，触发后主体才出现 | 游戏事件必须立即可辨；检查可听主体的起点，不能只检查第一个非零采样 |
| 蓄力起手、循环、满蓄各自好听，组合却像三套声音 | 先定一个主音色和完整动作结构；新增层不能重复争夺“正在聚力”的表达 |
| 满蓄用清脆的“叮”，与聚力风不衔接 | 满蓄应延续已有聚气，并用短促收束确认，不自动套用 UI 提示音 |
| 低温度生成的发射 A／B／C 仍明显不一致 | 低温度不能保证同一音色家族；先固定获认可母版，再尝试微小变化或共同主体加权混合 |
| 听起来像空文件，实际有有效声音 | 分开检查原文件、事件增益、地图补偿、本机配置、分组、空间衰减及声道预算 |
| 本体反弹做成木箱敲击、金属叮声 | 发声主体仍是人物身体撞击与回弹气流，材质只是差异；不是让玩家敲道具 |
| 普攻出手做成泛化的厚破风，剑刃感不明确 | 用户要求的是剑划过空气：突出细窄、清晰的刃风与锋利质感；不能只强调厚度、柔韧空气或身体冲劲 |
| 单条音效网页预估 3 积分，工具任务记录 6 积分 | 同参数核对网页和工具的实际生成入口与计价；不能直接沿用历史扣费，也不能未经证实将差额归因于归一化 |
| 整件围栏都用金属声，石柱也跟着响 | 按实际撞到的碰撞部位读取材质，不能凭建筑类型猜测 |
| 音库删掉了变体，奔雷或壶兽仍会直接播放 | 同时检查持有独立素材数组的技能与怪物入口，统一执行地图排除清单 |
| 正式池已经更新，网页或分组串听还是旧声音 | 同步单项音频、内嵌数据、分组 WAV、时间表、名称与停用说明 |

## 提示词审核与积分控制

生成前在当前会话交付一张简短的制作说明：对应画面与事件、想保留的音色特征、需要避免的冲突、完整提示词、条数、时长、循环方式、可用参数和预计积分。用户能直接审核的应是将要提交的完整文本，不能只给方向后自行扩写成另一种声音。

提示词使用简洁自然语言，写清**谁发声、做什么、声音怎样变化、何时结束、是否循环**。只加入影响交付的约束，避免大量抽象形容词、反复堆叠“厚重、史诗、强烈”，也不把一次声音写成复杂的多段电影演出。

可按下面的结构准备审核内容；其中占位项必须根据当前画面填写，这不是已获批准的生成提示词：

> 为［实际游戏事件］制作［单次／循环］音效。主体是［具体声音来源］，从触发开始立即出现［可辨主体］，按［动作运动与力量变化］发展，以［收束或尾音方式］结束。延续［获认可音源的特征］，适合［实际播放密度］。避免［已经确认不符合画面的声音］。

先做一条试听，方向成立再扩展。一次确认不授权自动补齐起手、循环、满蓄、发射及全部变体；用户已经指定数量时按该数量执行。额外付费重试先说明本条哪里不合适、下一次只改什么，再由用户决定。保留已确认的部分，不用连续生成来碰运气。

数量、时长、功能选项可能影响计费，不能把“一次任务”当成“一条的费用”。本轮预算按本轮授权执行，不把之前整包预算或历史扣费当成长期授权。提交前核对当次公开工具与可核实费用，完成后区分预计值与实际扣费；没有实际依据时不报精确积分。

单条 0.5 秒曾发生网页预估 3 积分、现有 Skill 任务记录 6 积分的差异。核查时网页公开计价为每秒 5 积分，乘数量后向上取整；工具调用的生成入口与网页不同，但旧入口具体计费明细尚未确认。该案例不能外推为固定费率，也不能据此认定某个开关加价。遇到同参数价格不一致，先停止后续付费生成并说明差异；改提示词、换入口或重新生成都不能自动获得再次扣费授权。

任务中断后先按原任务恢复查询，避免重复提交、重复扣费。沿用项目“不新增调用日志或同步页面”的约定；必要的数量、处理内容与费用在当前交付说明中说明，不另建流水记录，不保存凭据或隐藏服务字段。

## Meowa 模式和参数怎么选

每次制作先读当前可用的 `game-assets` 技能、音频说明及公开 `sound-run` 帮助，使用受支持的入口。以下是选择原则，工具支持范围以当次版本为准。

| 项目 | 选择原则 |
| --- | --- |
| 单条、音效包、变体 | 单条验证方向；`--sound-pack` 用于不同功能的一组音效，`--variants` 用于同一事件的变种，两种模式不能混用 |
| 数量 | 批量模式显式填写 `--count`，不依赖默认数量；同一事件做更多条不等于更好 |
| 时长 | 0.5 秒适合部分短促发射、命中和确认声；循环、传播或较长动作按实际需要选择，不能全部固定成 0.5 秒 |
| 实际输出长度 | 请求时长不代表最终文件精确等长；检查文件实际长度和有效主体，不用补静音制造“达标” |
| 循环 | 只有确实需要持续播放才用 `--loop`，并实际验证首尾与长按听感 |
| 温度 | 本轮讨论过约 0.2 的低变化尝试，但仍产生明显差异；只在公开工具支持时使用，不能以低温度承诺音色一致 |
| 归一化 | 开关不能代替验收；即使请求开启，也要测最终文件的短时响度与峰值，不假定返回已经一致 |

公开工具没有提供的参数，不自行拼接隐藏请求绕过限制。参数或费用不确定时先核实，不把之前会话的调用形式直接照搬。

## 成套声音与变体的一致性

**先确定可反复听的母版，再制作变体。** 同一事件的各条应保留相近的起声、主要音色、力量重心、有效时长和尾音。可以有细微音高、气流比例或短尾变化，不能把湿黏爆破、硬敲击和电子提示当成一个随机池。

若独立生成差异过大，可在已同意的范围内对现有片段做混合：保留稳定的共同主体，辅层只小幅改变权重；先匹配各层响度并对齐主要起音，再混合，复查峰值和单次动作感。百分比不是听感占比，未匹配响度的 10% 辅层仍可能压过主体。混出多次撞击、拖长前奏或盖住母版时，应减少层数，而不是继续叠加。

发射加权试听曾用原变体 2 作共同主体、候选作少量辅层，但这只是试听试作；用户最终选择正式发射仍只用原变体 2。**已有文件或混合方案不等于获得接入授权。** 一个稳定合适的声音可以先单独使用。

成套动作要同时试听“按住 → 满蓄 → 继续按住 → 松手”，以及取消和快速重按。当前蓄力以聚力风为主体，满蓄短促收束；不能为了增加层次重新补回用户已停用的其它蓄力声。

## 文件和听感验收

短促战斗音优先沿用项目现有的 **48 kHz、单声道、16 位 PCM WAV** 交付规格；Meowa 原始文件另行保留。单纯更换扩展名不等于完成格式转换。空间事件的单声道与音乐、环境素材的声道要求分开处理。

- **起声：** 从触发开始应能辨认主要动作。统计静音、弱前导与可听主体的位置；需要修剪时保留起音，做必要的极短去爆音处理，不能靠提前触发事件掩盖素材延迟。
- **尾音：** 不留无用途的长静音或混响，也不能为凑时长硬切主体。循环停止须能自然短淡出，不出现咔声。
- **循环：** 连续播放多次检查接缝、周期性重击与持续疲劳感。生成了循环标记，不代表听起来已经无缝。
- **响度：** 同一类变体先匹配可听主体的短时响度，再检查峰值余量。峰值相同不等于一样响，靠一处尖峰也不能代表整体力量。
- **混合：** 叠加后重新检查削波、刺耳、低频堆积和主体辨识。试听与游戏事件尽量使用同一混音基准，避免网页很响、游戏很小。

本轮部分短音试听曾按 100 ms 短时 RMS 约 -18 dBFS、峰值上限约 -3 dBFS 做匹配，这是当次比较方法，**不是所有音效的统一母带标准，也不是 LUFS 指标**。持续风声、主要命中和轻伴随声应保留各自层级。

“几乎听不到”先按链路排查：**源文件 → 事件基础增益 → 地图事件补偿 → 本机单条增益／静音 → 空间衰减与声道预算 → 分组音量与总输出**。棱晶／镜印旧命中素材曾有有效波形，但原播放增益较低；该次通过响度补偿处理，不需要重新制作一套音源。

本机配置保存在 `user://audio_mix.cfg`。验收项目默认值与本机试听配置时分别核对，不能悄悄覆盖用户存档，或把本机静音当作项目已正式停用。

## 接入现有游戏链路

| 入口 | 后续制作需要遵守的规则 |
| --- | --- |
| `data/audio/core_sound_bank_world.tres` | World 音源选择、覆盖和排除清单；共享音库与 City 的选择分别保留 |
| `MapEffects/CoreFeedbackAudio` | 消费真实动作、命中、生命与波次事件；不以视觉播放推算伤害或死亡 |
| `MapEffects/GameAudio` | 共用预算、优先级、密集合并与混音；`sound_selection` 还约束直接持有音源的技能和怪物 |
| `data/audio/combat_balance_world.tres` | 地图的事件补偿、优先级与同类限制；不把所有素材强行调到同样响 |
| `scripts/core/collision_surface.gd` | 读取实际碰撞部位材质；身体默认、形状覆盖，声音端不增加建筑类型分支 |

奔雷按片发声，后续传播逐层减弱；连续命中、经验和群杀按既有规则合并，不按每只怪物堆满声道。危险、主要命中与击杀要能辨认，持续气流和环境声音为它们留空间。需要增加反馈时先检查层级和触发密度，再增加素材数量。

蓄力循环跟随真实动作状态，取消／发射短淡出，快速重按接续；飞行循环随真实余速变化，结束时淡出。升级冻结同步暂停，重试和退出清理。击杀与尸体抛飞、落地、碰墙分别消费真实事件，不能把所有阶段都在死亡瞬间播完。具体哪些阶段当前有声音，以地图配置为准。

停用必须同时覆盖音库和独立入口。原文件、UID、配套导入文件及试听编号保留，避免影响其它场景与后续恢复；旧槽标明停用，不能重新编号或用未认可的新素材悄悄替换。

| 范围 | 已确认选择 |

| 满蓄 | S03 聚气收束，只在首次满蓄确认一次，长按不反复提示 |

| 本体反弹 | 石／木／金属分别用独立的已认可音源，主体仍是身体冲击与回弹气流 |

| 最近停用项 | 人物受伤两条、战败、部分雷击／受击／普通死亡变体、旧史莱姆死亡、壶兽碎裂和尸体落地／碰墙；不得借新音效包自动补回 |

## 交付和验证

试听页需提供明确名称、事件用途、变体编号和“正式生效／试听候选／已停用”状态。保留原声与调整后的对照时明确标注；分组串听只包含当前生效项，时间表与实际音频一致。离线页优先使用可直接播放的内嵌音频，避免本地页面因跨文件加载失效而出现“按钮不响”。

当前逐条试听入口为[战斗音效试听页](../../deliverables/combat-audio-review-20261019/index.html)。修改后同步其中的单项、内嵌音频、分组文件、时间表和停用提示，不能只改某一个 WAV。

数据与链路可使用无界面用例验证：

```powershell
# 在 demoWithMeowa/1 下运行，GodotPath 填写本机实际 Godot 可执行文件。
.\tools\run_tests.ps1 -Test @('test_world_audio_selection', 'test_world_audio_retirements', 'test_game_audio', 'test_audio_mix') -GodotPath '<Godot 可执行文件>'
```

人工验收至少覆盖单条试听、动作连续试听、BGM／雨声同时存在的战斗，以及密集怪群中的连续触发。重点听是否即时、是否同一音色家族、主要反馈能否辨认、长按是否疲劳、取消和快速重按是否干净。遵守项目约定，不自动启动渲染窗口或截图；无界面测试通过不能代替听感认可。

交付时说明哪些已接入、哪些只供试听、哪些待重做、做过哪些剪辑／响度处理，以及本轮实际可核实的积分。**用户已经拒绝的方向，不因工具输出看起来合格而重新接入。**
