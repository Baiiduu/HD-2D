# 伤害数字框架

正式波次场景已接入 `DamageNumbers`。人物普攻／飞行挥剑、A01、A02、棱光弹射、反射镜印、奔雷涌潮共用同一条反馈链路。

当前完成事件、运动、样式、相机投影与节点复用。伤害数字采用 CodeMan38 的 **Press Start 2P** 粗像素字体，原始文件、来源与 SIL OFL 1.1 许可证放在 `assets/fonts/press_start_2p/`。重击、暴击资源仅预留表现和预览，没有新增重击／暴击判定、倍率或概率。

## 结算与显示

`WaveEnemy.take_damage()` 完成原有资格检查和扣血后，通过 `damaged` 信号发出 `CombatDamageEvent`，每次有效扣血一次。数值采用实际扣除生命，溢出伤害保留在 `requested_amount`，不会把无效命中、出场保护或冻结期间的攻击显示成伤害。

巨量怪潮模拟仍经过相同资格与命中检查，但锁定怪物生命。事件标记 `simulated`，实际扣血 `amount` 保持 0，显示层通过 `display_amount()` 读取完整的 `requested_amount`，保留真实攻击、技能等级与成长数值，不按剩余生命截断；不会触发死亡、奖励或分裂。普通战斗继续显示实际扣血。

事件保存实际伤害、请求伤害、来源、表现标签、方向、目标 ID、世界锚点与致死标记；不保存怪物或武器节点。数字停留在本次命中位置，怪物移动或释放后仍可完成动画。`get_damage_feedback_position()` 可供新怪物重写；现有史莱姆和具体怪物使用实际 Sprite 尺度和画布高度。

显示器监听当前会话的 `enemy_spawned`，自动连接新怪物，包括分裂幼体。新怪物继续继承 `WaveEnemy` 并通过波次登记即可，无需分别写飘字。

## 新攻击接入

保持原有伤害公式，只在真实命中处提供可选反馈信息：

```gdscript
enemy.take_damage(final_damage, {
	"source": &"new_weapon",
	"style": &"lightning",
	"direction": heading,
})
```

旧的单参数 `take_damage(final_damage)` 仍有效，使用普通样式。方向为世界向量，显示器在出字时换算为当前相机的左右方向。不要额外手动调用飘字，否则同一次伤害会重复显示。

独立预览或其它已结算的伤害来源可构造 `CombatDamageEvent` 并调用 `DamageNumbers.present(event)`；这个接口不扣血，也不参与攻击判定。

## 样式扩展与参数

资源位于 `demoWithMeowa/1/data/combat/damage_numbers/`：

| 标签 | 字号／起跳放大 | 当前用途 |
| --- | --- | --- |
| `normal` | 40／1.3 倍 | 人物基础剑术、A01、棱光弹射、反射镜印 |
| `lightning` | 40／1.3 倍 | A02 与奔雷涌潮 |
| `heavy` | 56／1.45 倍 | 暖金重击表现预留，仅预览使用 |
| `critical` | 64／1.5 倍 | 金红大字与感叹号预留，仅预览使用 |

字面采用原字体建议的 8 像素倍数字号，关闭字体抗锯齿、MSDF、微调和子像素定位，数字节点使用最近邻采样。连续命中的纵向间距为 40 逻辑像素，横向仍按字宽与放大倍率留空。离屏判断计入实际字面尺寸和动画放大，避免多位大数字提前消失。其它 UI 字体保持各自配置。

新增 `DamageNumberStyle` 资源，填写唯一 `style_id` 并加入 `number_styles` 即可。未知标签、空样式槽会回退普通样式。`source` 负责识别攻击来源，`style` 负责选择外观，两者不绑定伤害公式。

Godot 正式场景入口：`WavePrototype → DamageNumbers`。统一参数面板位于“战斗与成长”，可以编辑各样式的字体、字号、颜色、描边、投影、后缀、小数位，以及压缩、上升、顶点停留、回落、侧移、倾斜、消散和碎光。资源编辑会影响引用同一资源的场景；需要独立风格时先复制资源。字体和文本尺寸在新数字出现时确定。

同一目标按中、右、左交替分槽，不延迟首次反馈、不合并伤害。横向间距同时考虑字宽、描边和放大倍率；相机旋转时重新投影世界锚点，背后及屏幕外的数字隐藏，生命周期继续推进。当前不做建筑遮挡射线查询。

## 生命周期与性能

- `DamageNumber` 不单独逐帧处理，不使用每击 Tween 或 Timer；显示器集中推进活跃节点，没有数字时停止处理。
- 默认预热 24 个节点，闲置池保留最多 128 个。上限只限制闲置节点，密集命中仍按真实次数创建，超出部分完成后释放；目标分槽状态随最后一个数字回收。
- 数字不接收鼠标输入，独立于场景灯光和景深，不跟着怪物闪白或变暗。
- 加入会话的战斗冻结机制，升级选择冻结动画；管理界面沿用原有世界运行规则。清波休整保留尾段，新局、结束、撤退时清空。
- 普攻与击杀短顿期间，数字用单调时钟的真实经过时间继续播放，不用当前 `Engine.time_scale` 反推本帧时长，避免切入时将新数字直接推进至过期。普通战斗仍沿用战斗时间；闲置唤醒、冻结／恢复和清理都会重新同步时钟，不补算冻结或闲置时间。
- 当前碎光为可调的简单方形占位反馈；后续定稿字体或更丰富素材可替换显示层，不改技能和伤害计算。
