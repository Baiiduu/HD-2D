# 怪物接入、调参与大规模数量框架

新增功能的公共查询、位移提交、障碍缓存失效、可执行范例及统一功能检查，见[战斗共享优化接口](../technical/combat-extension-framework.md)。

当前正式地图通过 `WavePrototype` 管理出场队列与生命周期，`WaveEnemy` 管理生命、出场保护、死亡和取消，具体怪物实现移动与攻击。目录已登记史莱姆、卷叶冲锋虫、灯囊花兽、裂瓷壶兽、响铃苔蛙与蓝胶幼体；四种新怪已完成 Meowa 像素素材、独立招式、前三波与无尽编排接入，并使用正式场景的实际镜头完成原生渲染预览。精英、首领仍是编排分类与容量接口。

普通波次保留 18／28／40 的开场，后续容量与增长通过 `WavePrototype.population_rules` 配置；模拟数量与持有技能独立配置，以当前资源为准。无尽怪物生命从基础值逐步成长；World 前段到百倍后保留成型窗口，第 22 波起继续温和增长、最终安全上限千倍；City 与共享默认保留十倍线性曲线。当前性能目标为同屏一百多只怪物时约 100 FPS，同场总量由后续无尽配置决定；先以 128／160 只同场作可重复对照，同时报告视锥内数量。采用纯 GDScript，主验收围绕基础剑术与人物本体弹射，AutoFan 不纳入后续正式玩法，其它射击弹幕技能待定。数量配置不代表帧率已达标。

原 512 档和 768 压力档继续保留作为极端诊断配置，正式地图尚未启用；不再把 500 只同场作为当前验收门槛。

| `data/enemies/pot_brood.tres`、`mini_slime.tres` | 母体与幼体独立数值、幼体标识、分裂延迟 |

| `data/waves/population/horde_128.tres` | 正式地图已接入；渐进容量与模拟均可调整，名称不锁定实际参数 |

| `data/waves/population/stress_768.tres` | 直接同场 768，单波最多 2304，供压力验证 |
| `data/waves/endless_health_growth.tres` | 无尽生命成长起始波、每波增幅和倍率上下限 |

Godot 的“参数总览 → 战斗与成长”可搜索怪物目录、基础生命、碰撞半径、接触距离、容量成本、同种上限、三份数量预设及无尽生命成长规则。将目标资源赋给正式地图 `WavePrototype → 波次配置 → Population Rules / Health Growth Rules`，保存 `scenes/world/world.tscn`，新挑战／重试生效。未连接的预设不会因编辑参数而自动启用。

设置数量档位后，它覆盖原同场上限、单波登记预算、无尽数量增长与间隔、刷新工作预算和出场间距；原控制器参数仍用于不设档位的兼容模式。安全距离、禁止区域、堵点超时与受击保护继续由控制器调整。档位不自动开启无尽模式。

## 四种怪物当前行为

| 怪物与标识 | 招式 | 自动怪潮参与 |
| --- | --- | --- |
| 卷叶冲锋虫 `leaf_charger` | 接近后蓄力并锁定方向，沿预告直冲；碰墙或人物停止，进入恢复 | 权重 1.2 |
| 灯囊花兽 `lantern_spitter` | 中距离停步、蓄力后吐一粒直飞种子；人物靠近时退步 | 权重 1 |
| 裂瓷壶兽 `pot_brood` | 慢追与接触伤害，死亡按原尺寸拆成小碎片；先登记两只幼体，再移除母体，延迟生成 | 权重 1.6 |
| 响铃苔蛙 `bell_frog` | 蓄力后鼓舞范围内同高且无遮挡的普通同伴，提供有限时间的移速倍率 | 权重 0.4 |
| 蓝胶幼体 `mini_slime` | 独立小体量追击／接触；只从壶兽分裂进入，死亡不再分裂 | 权重 0，不直接刷新 |

分类、容量成本、同种上限和战斗数值以各怪物资源为准，生命仍参与既有无尽成长。鼓舞不回血、不护盾、不影响自身、特殊、精英或首领；不同来源取最强值而不相乘，来源死亡或取消立即移除对应增益。种子不追踪、不反射，碰墙销毁；发射者死亡后已经出手的种子继续沿世界轨迹飞行。所有怪物来源共享受击保护。

前三波主体数量仍为 18／28／40，原史莱姆集中批次改为 10／14／18 只目录混合怪潮，从第一波开始包含全部五种主怪；固定史莱姆散兵与错时增援保留。怪潮自动读取目录中 `horde_weight > 0` 的怪物，后续无尽波继续沿用混编。幼体权重为 0，只由实际壶兽死亡登记；主体数量上限不包含实际分裂出的幼体，所有个体仍占用同场容量与单波登记预算。详细规则见[怪物刷新](wave-spawning.md)。

局部生成保留墙体、留空、地形、导航与同场预算检查，使用人物碰撞留空距离替代普通边界刷新的五米安全距离，使近身击杀后的幼体留在母体附近。入口禁刷矩形只约束普通外围增援，不阻止母体进入该区后的原地分裂；否则整个局部搜索范围可能被矩形覆盖，队列会永久等不到落点。幼体沿用直接激活的出场规则；母体死亡、待生成队列和幼体全部结束后才清波。未登记的幼体和继续裂殖的壶兽幼体在开局前拒绝。

在 Godot“参数总览 → 战斗与成长”搜索怪物名称、冲锋速度、种子飞行速度、分裂幼体标识或鸣铃鼓舞半径，选择对应资源调整；新挑战／重试生效。招式声音在各怪物场景中指定，交给共用 `MapEffects/GameAudio` 的预算与混音。全场主预告最多两处，结束、死亡、取消即释放。

美术位于 `assets/meowa/enemies/`，保留原生透明像素。四主体为 80×80 动画画布，每种有五个独立方向，左侧方向镜像复用，运行时覆盖八向；行走与三种蓄力动作均保留八帧，人物缩放后实际像素密度为 0.016 米／像素。幼体为 52×56 画布中的微小蓝胶，使用完整八帧轻跳。壶兽碎裂从死亡帧的图集区域和朝向拆开，不缩放或重采样素材。

四种怪物统一在正式地图的实际波次或巨量怪潮模拟中观察；招式和死亡分裂由真实战斗触发。旧的定时击败壶兽演示入口已清理，怪物与分裂的自动回归继续保留。

## 接入新怪物

1. 准备怪物场景，根节点继承 `WaveEnemy`。同类追击／接触行为可以复用史莱姆场景；不同招式另写子类，保留场景的原生像素、美术与动画。
2. 创建一份独立怪物资源。普通通用行为使用 `WaveEnemyDefinition`；追击／接触行为使用 `WaveMeleeEnemyDefinition`。填写唯一 `enemy_id`、`scene`、名称和数值，保存到 `data/enemies/`。
3. 将资源加入 `enemy_catalog.tres` 的 `enemies`。`horde_weight` 默认 1，下一局／重试自动进入现有混合怪潮，不必逐波添加；需要专属召唤／分裂的怪物将权重设为 0，仍建立本局快照并支持按 ID 生成。
4. 如需固定种类的散兵或增援，在波次 `WaveSpawnEntry` 关闭 `mixed_horde`，填写 `enemy_id` 或直接拖入 `enemy`。只用标识时 `enemy` 留空；二者同时填时必须指向目录里的同一资源。开启 `mixed_horde` 的组则自动选目录成员，共用该组的数量、节奏和区域。

新增怪物不需要在波次控制器里增加类型判断。仍可直接引用未登记的旧资源；需要按 ID 召唤时必须登记目录。当前登记的 ID 为 `slime`、`leaf_charger`、`lantern_spitter`、`pot_brood`、`bell_frog`、`mini_slime`；具体资源以 `enemy_catalog.tres` 为准。

### 通用数值

| 参数 | 史莱姆值 | 含义 |
| --- | ---: | --- |
| Health | 20 | 初始生命 |
| Health Growth Enabled | true | 参与无尽生命成长；关闭可用于固定生命的特殊怪物 |
| Move Speed | 1.35 米／秒 | 波次移动速度 |
| Attack Damage | 8 | 传给实际招式的伤害 |
| Experience Reward | 3 | 真正击败后的局内经验；召唤体可为 0 |
| Spawn Clearance | 0.35 米 | 出场留空与碰撞检查半径 |
| Navigation Radius | 0.32 米 | 共享导航的实体通行半径 |
| Role | Common | 普通／特殊／精英／首领 |
| Population Cost | 1 | 容量点消耗，属于规划预算而非性能测量 |
| Max Alive | 0 | 同一资源同时在场上限；0 使用全局预算 |
| Horde Weight | 1 | 自动混合怪潮的出场权重；0 排除，仍支持固定编排与召唤 |

### 接触型专属数值

史莱姆波次实例从 `WaveMeleeEnemyDefinition` 应用身体半径／高度、重力、路线刷新间隔、局部避让半径／强度、接近停止距离、接触攻击距离／高差、击退倍率、动画速度、预告缩放与受击闪光。展示模式仍沿用场景原有巡逻参数。

身体放大时同步调整高度、刷新半径和导航半径；两种留空半径须覆盖身体半径。外观像素尺寸和脚底偏移仍由怪物场景负责。接近停止距离必须小于实际接触距离，否则攻击怪会停在攻击范围外。动画速度独立于移动速度。

其它招式用 `WaveEnemyDefinition` 子类导出其参数，并覆盖 `validation_error()`，先调用父类校验。`configure_wave(context, definition, warning)` 在入树前调用，子类先调用父方法，然后读取自己的类型化资源；不能在这里访问尚未初始化的 `@onready` 节点。

怪物、数量与生命成长规则在新挑战时建立副本，场景与美术资源继续共享。运行中编辑 Inspector 的原资源，下一局／重试生效。每只怪物出生时记录当前波号与最大生命，后续不会修改已出生怪物的生命；伤害、速度与经验继续读取各怪物基础资源。

### 生成前的落点剪影

World 通过独立配置 `data/combat/scenes/world/waves/spawn_shadows.tres` 开启「影子先到」；City 保持当前配置。参数总览「视觉」搜索「怪物落点剪影预告」，可调整开关、预告／消散时长、剪影与细边颜色／透明度、尺寸、贴地纵深和收束比例。默认预告 0.55 秒，出怪后的地面余影 0.12 秒；旧 `spawn_warning`／编排 `warning_seconds` 兼容字段不控制此效果。

队列到期并取得容量后先预留合法落点，尚不实例化怪物；数量、同种、分类、容量点和整批预留都包含预告中的个体，预告落点之间遵守原生成间距。到期重新检查原落点的地形、墙体、人物留空、怪物占位和可达性，成功后在同一位置生成。失效则立即撤销预告并按原重试间隔重新选点，重新播放完整预告。普通外围、怪潮和局部分裂／召唤共用此流程，局部生成仍使用自身的安全距离。怪物真正出生后仍为完整尺寸／透明度并立即参战，没有第二段出生等待。

`WaveSpawnShadowAtlas` 在目录预热时读取各场景 Sprite 的原生帧，烘焙主体和一像素细边到同一图集；同一目录重试复用，素材发出变更信号后下次预热重建。当前六种怪物自动适配。`WaveSpawnShadows` 共用一个 MultiMesh、材质和无光照贴地 shader，每个落点一层小贴片、不投射阴影，绘制保留真实场景深度遮挡；等待阶段只更新公共战斗时钟，CPU 仅检查已出生的短消散尾段。Q/E 调整贴地朝向，脚底始终固定在预留世界位置。冻结时计时与图像同停，正常清波、失败、重试、返回菜单及退出清理全部预告和余影。

`test_spawn_shadow_queue` 验证无界面调度与预算，`test_spawn_shadows` 验证实际怪物图集、128 个实例共享绘制数据、真实地形生成、动态墙体、冻结和清理。它们不验证画面或 GPU 帧时间；正式地图的可读性、密集重叠和开关性能对照仍须人工验收。

### 密集人海与聚群间距

怪群允许前后遮挡身体，保留能辨认个体的头部和肩宽。追击与局部退步保留避让后的速度大小，前排受阻时后排减速，停止追击后仍整理站位；不再将避让方向强制归一化为满速。射手待机时可以让位，招式预告／恢复、锁线冲锋和眩晕保留原有运动规则。

普通追击在空地按各怪物当前方位靠近，跳过多余的网格中心；绕障时只前视到身体可直达的拐角。捷径逐段检查中心及身体两侧的地表相接、坡面高度和当前墙体，跨水、断层、折坡与不安全墙角交回原路线。刷怪与残怪连通判定继续使用严格共享导航。

后排前进方向明显受阻时，沿现有局部避让压力较小的一侧轻微让行；对称堵点使用稳定的个体侧向，拥堵期间不逐帧随机改向，一侧不安全则尝试另一侧。让行强度在近身时渐弱，保留前排停靠、接触攻击、人物柔性留白及原聚群间距，不指定包围槽位或扩大固定圆阵。

参数总览「战斗与成长」可搜索「追击路线前视距离」`pursuit_lookahead`（默认 4 米，8 米内可直达时直接靠近）与「追击侧向让行强度」`pursuit_flank_strength`（默认 0.35）。分别设为 0 可对照原网格路线或关闭侧向让行；怪物目录内各资源独立调整，下一局／重试生效。它们只改变普通追击，射手局部退步、锁线冲锋和预告保持原规则。

普通追击的朝向使用原来的寻路意图，受阻或停止追击时面对目标，不把避让产生的微小往返当作转身。射手原地让位同样保持面对目标。八方向显示在分界处保留 6° 余量，避免相邻素材反复切换；真正转向与 Q/E 旋转仍即时更新，不改聚群站位、实际速度、攻击预告或动画帧率。

正式地图的人物启用柔性近身留白。参数总览「人物」搜索「人物周身留白距离（额外）」，或选中 `Player → 怪群近身留白`，对应 `crowd_clearance_distance`，单位米，默认 0.12，0 关闭。它增加普通怪原有停靠距离，并平缓限制向人物靠近的速度，避免后排避让压力把前排重新挤到人物身上；人物主动贴近时，怪物按正常移速让位，不改变人物碰撞体或移动。距离围绕人物实时计算，运行中修改 Remote 人物参数会影响现有怪物；编辑本地场景参数后重新运行生效。

接触近战的停靠距离最多到原接触攻击距离内侧 0.05 米，保证仍能命中；继续调大留白值不会把近战怪隔到攻击范围外。原本在接触范围外停靠的远程／冲锋接近保留各自距离。锁线冲锋、预告／恢复停步、拨怪外力与眩晕不施加留白约束。`tests/test_player_crowd_clearance.gd` 检查真实资源的停靠与接触命中、实时开关及上限、128 只挤压、移动跟随和特殊运动。

参数总览「战斗与成长」的常用项中可搜索「聚群目标间距」与「聚群避让强度」，分别对应 `separation_radius` 和 `separation_strength`。目标间距越大越疏，强度越大越不易压紧；目标是舒适中心间距，拥挤时允许适度压缩，不等同于硬碰撞直径。普通怪默认 1.0 米，冲锋虫 1.1 米、灯囊花兽 1.05 米、幼体 0.5 米，强度默认 1.5。混合体型取双方间距平均，并在接近身体接触距离时增强排斥，完全同点会沿稳定的相反方向分开。

避让复用 XZ 空间索引，新增体型／间距缓存随实体移动和配置更新，移除时清理；最大间距仅在索引生命周期内保留保守上界，清空索引时重置。不同高度和出场预告不互推，不新增全体两两扫描，不调整碰撞体、导航通行半径、攻击判定或动画帧率。`tests/test_enemy_crowd.gd` 对照 128 只持续追击的旧聚堆与当前人海，检查最近邻间距、聚集范围、继续推进、同点解开和混合体型。

## 无尽生命成长

## 巨量怪潮模拟

在正式地图选中 `WavePrototype → Population Rules`，可选择 `data/waves/population/mass_horde_simulation.tres`。该预设默认 512 只，开启 `Simulation Mode`；现有数量资源也可以开启同名选项。

- `Simulation Enemy Count` 是本波目标数量，允许 1～4096。模拟会在第一波集中登记这些怪物，自动适配本局同场、分类、容量点和登记预算，无需等待无尽波次增长。数量不保证帧率或地图承载能力，真实安全位置、分帧工作预算、碰撞与可达性检查继续执行。
- 展开 `Simulation Skills` 配置持有技能，每个条目选择 `Skill Definition` 并设置 `Skill Level`。等级 0 表示不携带，上限取技能当前真实配置；空列表只保留基础剑术。专用预设已列出雷光贯穿、棱光弹射、反射镜印和奔雷涌潮，默认各 1 级，可直接调整，也可添加其他已接入的技能资源。重复技能、超限等级与未接入当前场景的技能会在出怪前明确报错。
- 按 F 直接应用模拟技能，不经过开局抽卡。基础剑术、飞行挥剑及技能按正常攻击和成长数值显示伤害数字；怪物生命锁定，攻击不会杀死怪物或触发死亡奖励、壶兽分裂。命中反馈、技能目标预算与镜印反射继续运行，拨怪和眩晕遵守正式规则开关。人物免伤仍保留怪物真实招式与共享命中间隔。
- 本模式只有一波，顶部显示当前在场／目标数量和双方不扣血提示。ESC 结束，T 重试读取新的数量和技能配置；过程中编辑资源不会改变本局快照。结束会清理怪潮并解除生命锁定及临时技能开关，切回普通规则后恢复常规扣血与开局选择。

`tests/test_horde_simulation.gd` 验证数量与技能配置、真实攻击飘字、怪物生命锁定、人物免伤、正式拨怪开关、重试、资源隔离和普通模式恢复；加 `-- --large` 使用完整 AI 与碰撞运行默认 512 只模拟，不作为帧率验收。

## 怪物行为契约

- `_combat_tick(delta)` 实现移动和招式；父类负责预告倒计时。预告中不移动、不攻击、不受伤，但占用容量。
- `can_damage_player.call(amount)` 做廉价资格判断；命中前继续做准确的距离、高差、碰撞／遮挡检查，再调用 `damage_player.call(amount)` 结算。所有来源共用受击保护。
- 弹丸和危险区域挂在 `attack_root` 下，清波、结束时统一取消。需要敌人死后保留的弹丸也放在这里。
- `_on_defeated()` 内先通过 `request_spawn_by_id.call(id, count, delay, global_position)` 或原 `request_spawn.call(definition, count, delay, position)` 登记幼体，再让父类发出死亡。不要直接添加未登记怪物节点。
- `apply_knockback(direction, distance)` 由具体怪物实现反应，史莱姆读取击退倍率并保留真实地形／碰撞校验。
- `apply_stun(base_seconds)` 读取怪物的独立眩晕时长倍率，同类效果取较长剩余时间；受控期间由 `_stunned_tick` 保留重力及碰撞，外力仍继续。特殊招式通过 `_on_stun_started` 取消当前预告和动作，恢复后重新完整预告。当前普通怪 1 秒、壶兽 0.5 秒，详见[拨怪眩晕](player-ricochet.md#拨怪眩晕)。
- 子类覆盖 `_physics_process` 或 `_exit_tree` 时调用父方法。共享位置索引在移动后更新；额外瞬移／击退后调用 `spatial_index.update(self)`。不要直接改共享拓扑，地形变更走现有重建接口。

登记预算包含本波全部已生成与待生成怪物，以及召唤和分裂。预算耗尽、错误标识、无效资源等会明确中断，避免无限衍生或伪造清波。休整仍没有倒计时，按 F 主动继续；升级只冻结战斗与战斗计时。

## 大规模运行方式与验证

原史莱姆逐帧遍历全部同伴进行避让，现在使用世界 XZ 哈希格，仍计算全部实际半径内同伴，不截断邻居、不减动画帧、不减伤害结算频率。避让直接累计候选，避免为每只怪物创建邻居数组和重复计算距离。

索引以稳定整数槽位存储每怪的位置、预告资格、体型和原 ObjectID，位置与资格使用 Packed 数组，半径／间距保留 Float64。移除时释放槽位，重入按原桶顺序追加；每次移动／拨怪后即时同步，不使用整帧旧位置快照。不额外分配 ObjectID，保留全部邻居、同点分离、稳定让行、混合体型及运行时参数更新。

避让遍历半径覆盖格内的全部候选，按双方实时体型及间距做精确判定，保留原遍历及累加顺序。每格最大间距与格距下界的筛选试验虽减少候选，但在正式图 128／160 只同状态微测中增加耗时，现已撤回。`nearby`、`nearby_into` 与 `swept_bodies` 继续读取实时位置并保留返回顺序。

相同通行半径共用八方向导航图与反向最短路树。除上下左右外，加入四个斜向；斜向两侧的正交通路均须可走，再按实际身体留空扫掠斜线，不能穿建筑夹角、薄墙、水格或断层。追击按真实三维边长选路，斜线及坡面不再按一个等权步数计算；怪物继续归一化移动方向，斜走不加速。史莱姆、壶兽及其他复用追击接口的怪物自动适配，攻击招式与同伴避让独立保留。

固定半格中心被墙边留空挡住时，构图阶段可在原地表格内向周围八方向各尝试四分之一个采样间距；只有完整导航体型确实不重叠的候选才入图，仍使用原节点 ID、八方向连接和逐段实体扫掠。这样可表示足够宽但偏离采样中心的边路，不扩大地图、缩小怪物或放宽穿墙判定，也不增加逐怪的运行时补路查询。浅层贴墙目标的最近点若落在真实墙的另一侧，仅在附近同层连续地面上选择可见接近点；起点到接近点仍须由图证明连通，屋顶深层投影保留原回退。`tests/test_pursuit_narrow_passage.gd` 覆盖便利店与花坛旁真实宽度的偏心窄路、空气墙内侧目标、完整体型扫掠、实际残怪超时及真正封路／跌落。

同一目标导航点只建立一次共享最短路树，不为每只怪物重跑 A*；目标导航点变化或地形重建时更新。规则图使用密集前驱数组，距离和最小堆工作区在同一路径对象内复用，保留原 Float64 距离、松弛阈值、入堆顺序与同距选路。沿目标移动方向有限预计算邻近目标的完整树，全局最多一项运行、四项待算、十二份完成缓存；后台只读不可变图快照，不访问 AStar、Node 或物理世界。主线程重新读取当前禁用状态，仅采用同目标、同代次、完整快照一致且已完成的结果，复制后使用；未命中立即同步构建。手工图继续字典前驱回退。每物理帧重新检查目标遮挡，首尾段保留实时碰撞校验；实体移动仍逐帧保留真实碰撞。建筑／屋顶的原局部追击回退和严格刷新连通性继续区分。不同尺寸预热不同导航图，图不会随无尽波数或重复调参无限累计。

刷新与残怪保护只需判断连通性，复用安全目标选择后使用原生点到点查询，不因人物每帧移动而额外重建完整追击树。查询方向保持原树的目标到起点方向，临时禁用节点由当前图检查；首尾实时扫掠、邻近九格补选、水边及屋顶回退保持。实际 AI 仍按原刷新时机使用完整最短路树。

规则导航图在 `build` 后缓存邻接顺序、真实边长及精确最近点索引。局部最近点只有在距离能排除所有未访问空间桶时才返回，否则使用原生全图查找；保留同距最低 ID 与禁用点规则。运行时点位和拓扑变动通过 `build` 重建；替换图对象或改变点数的手工夹具回退原生查询。

拥挤让位与安全前视可复用 8×8 格静态地表的严格同高资格；只有路径及身体两侧的完整包围区均已认证时才跳过重复地表采样。数据编辑／替换、层高、格长、范围、变换和导航重建使缓存失效，坡面、水边及未认证区域保持原精确采样。动态身体扫掠和贴墙脱离检查每次执行。

普通追击与局部退步只在一次同步移动规划中复用起点、目标平面距离和有效移速，不保存为逐帧状态；移动后的朝向、接触距离、高差和遮挡继续读取实际落点。墙角补选只在同一次起点搜索内复用起点重叠及接触点，每个候选仍单独检查身体扫掠、离墙方向和终点重叠；下一次查询重新读取物理世界，不缓存动态障碍。

地形本身只有在整块矩形同高、没有水／桥／坡标记时合并碰撞三角形：保留顶面、实际外边界及外沿墙的高度和绕序，仍为开放底部的凹面形状。渲染网格、地表绘制、建筑碰撞与怪物胶囊不变；其它地形完整使用原逐格碰撞。几何编辑随正常地形重建重新判定，纯地表涂刷不重建碰撞体。

残怪保护使用一秒一轮的快照队列，按物理帧分摊检查并保留小数预算；单个长帧最多检查当前轮各怪一次。不可达时间按每怪实际战斗检查间隔累计，预告仍按原采样资格跳过，冻结不推进；开波、结束和重试清理队列及时间戳，同步结束后重开也用战斗代次隔离旧循环。

波次开场按组一次登记，只排序整波队列，避免数千只怪物逐只重复排序。每物理帧的生成、任务检查和位置尝试分别有工作预算；没有安全点时保持重试，持续拥堵明确中断。

波次怪物相同动画帧、受光、颜色和轮廓参数共用材质与网格，受击闪光独立选择材质，最后一只实例离场后释放共享缓存。翻转、换帧、图集原地变更和轮廓开关均使相应绑定失效；原 shader、动画帧率和遮挡精度保持。没有待生成任务或全局满员时，控制器跳过重复位置同步，实体移动后的索引更新继续执行。

怪物显示共用实际相机 Basis 对应的水平投影轴，同一渲染帧内相机或父节点旋转也立即重算；只缓存有界的方向片段名称与动作前缀，不持有相机或动画资源。SpriteFrames 的片段存在性、帧数、速度、时长与纹理仍实时读取，因为部分原地编辑不发出 `changed`。贴图与镜像赋值先比较 Sprite 当前真实属性，保留外部修改后的恢复、动画相位与六度朝向余量。

`tests/test_pursuit_tree_workspace.gd` 与原树构建器逐点比较距离、前驱与完整路线，验证工作区复用和禁用节点；`tests/test_terrain_collision_compaction.gd` 从未改的渲染顶点取得原碰撞几何，对照射线、边沿与胶囊真实移动，覆盖开底、落地、墙角、动态墙和几何编辑回退。

`tests/test_pursuit_tree_prefetch.gd` 验证真实后台任务与同步树逐点／完整路线一致、未完成立即回退、结果隔离、禁用／变换／数据／重建失效、有界队列和运行中 owner 释放。后台内核使用独立内存脚本快照；运行中热重载还检查任务句柄保留与回收、旧源码结果拒绝和新内核生效。

既有成长集成与参数总览继续验证。无尽生命周期测试显式关闭两个新规则，以覆盖旧控制器曲线的兼容性；新正式曲线由成长接入测试覆盖。部分早期测试仍假设开局直接获得技能和旧地图范围，任务中间目录保留适配副本。旧展示史莱姆测试有 8 项巡逻／坡道／菜单检查未通过，换回修改前怪物代码仍得到相同失败，属于现有基线问题，不据此宣称全项目测试通过。

真实数量压力入口为 `tools/benchmark_enemy_population.gd`。它加载正式地图、绑定原相机并等待跟随，使用原动画与天气，持续回血，不改场景、存档或参数资源。默认关闭武器和升级做怪物压力隔离；`--combat` 通过真实接口建立四种满级技能和封顶增益，使用十倍怪物生命，保留攻击、命中、死亡、经验掉落、吸取和补怪；仅在测试中提高升级门槛，避免选择界面冻结采样。`--walk` 用原人物输入与碰撞做周期走位，`--frozen-movement` 仅用于分离移动开销的诊断，不作为玩法帧率证据。

`--uncapped` 仅为采样解除垂直同步与帧率限制；`--counts=0` 提供地图空载对照，`--warmup` 等待追击进入稳定阶段。报告包含平均 FPS、中位数、P95／P99、物理耗时、活怪范围、击杀与掉落数量、相机参数、视锥内数量和原生设备信息。视锥计数不扣除建筑遮挡，不能等同于屏幕上完整可见的怪物；完整战斗补怪期间实际活怪数也须看报告范围。此次文件放在 `D:\.codexfile\work\enemy-300-growth`。
