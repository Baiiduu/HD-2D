# 攻击资源复用与性能

用户要求所有攻击在保持游戏效果的前提下尽量节约资源。当前覆盖 A01 全部等级、A02 实际投射物与视觉组件、史莱姆接触攻击；后续玩家、敌人、弹丸和范围攻击沿用下面的要求。

2026-10-15 最新验收方向为同屏一百多只怪物时约 100 FPS，同场总量待无尽模式配置决定；先以 128／160 只同场对照。继续纯 GDScript 优化，主要负载使用人物本体弹射与基础剑术。AutoFan 不纳入后续正式玩法，其它射击弹幕技能待定。下文 512 只与旧自动技能的数据保留为历史压力诊断，不是当前玩法的强制验收组合。

## 所有攻击的共同要求

- 固定网格、索引、图集和材质尽量复用；位置、旋转、缩放和播放帧通过实例更新，不逐帧重新创建资源。
- 重复出现的命中特效、弹丸等按实际需求复用对象。闲置时停止更新，取消或结束时完整重置；不预建大量尚未用到的对象，也不遗漏应显示的效果。
- 先检查阶段、冷却、已命中记录、范围、高差与角度，再做射线、地形采样和导航查询。
- 共享有明确有效期的查询结果，地形改变、战斗结束或相关参数变化后失效；动态挡墙实时检查。
- 不通过减少动画帧、改变伤害频率、删减并发特效、降低命中精度或关闭场景效果取得性能数字。声音沿用既有全局声音预算与合并规则。
- 新攻击接入时验证高等级、多效果和敌人密集情况，并回归墙体、台地、坡道、移动、闪身、升级冻结与清场。性能比较使用相同地图、镜头和参数，分别记录攻击 CPU 与整帧耗时。

这些要求规定复用和验证方式，不要求所有攻击使用同一种几何形状或一套庞大的通用武器框架。

## A01：保留完整斩光，减少重建

原双刃在每个物理帧重建两份网格，重复计算约两千次地面采样，且在排除不可能命中的敌人之前就做导航查询。

现在每刃使用 125 个独立顶点与 576 个索引，仍绘制原有 192 个三角形。空旷平地上两刃共享同一个网格，移动和旋转只更新实例变换；范围、角度或离地高度改变时重新生成。墙体继续实时裁切；坡道、水面、断层与台地边缘继续逐点贴地，仍使用相同三角形、纹理坐标和动画。

`scripts/combat/attack_surface_query.gd` 是战斗共用的地表查询服务，通过 `WavePrototype.get_attack_surface_query()` 获取。`flat_ground(origin, radius)` 判断完整范围及边缘缓冲是否为同高地面，`unclipped_flat(origin, radius)` 再检查挡墙，决定能否直接共享未裁切网格。有墙的平地只做实时墙面裁切，不重复逐点采样已经确认的地面高度。地形资格缓存限于当前物理帧，`TerrainData.changed` 或数据替换立即清空；动态障碍每次查询。其他贴地攻击可复用这个服务，不适用的攻击继续自行判断。

命中先过滤未出生／已死亡、已命中或尚在命中间隔中的敌人，以及不在扫过角度内的目标，再执行原有范围、地面高差、遮挡与导航判定。双刃仍共享同体命中间隔。闲置时不反复执行取消和隐藏操作，闪身、冻结与清场沿用既有行为。

## 当前方向：128／160 只与人物本体弹射

最新主验收取消旧的全自动技能满级组合，采用基础剑术和人物本体弹射；模拟仍保留真实 AI、接触、碰撞、拨怪、眩晕和命中反馈，人物免伤且攻击零伤害以维持固定活怪数。无尽同场总量待后续配置，128／160 只是当前可重复负载。

空间索引改用稳定整数槽位与平行 Packed 数组，半径／间距保留 Float64；逐怪移动后即时更新，仍遍历全部真实邻居，保留候选顺序、ID 同点拆分及槽位重入。同进程交替微测中，128 只的更新＋避让由 2.361 降至 1.923 毫秒，160 只由 2.907 降至 2.431 毫秒，分别约 19%／16%；4095 项旧实现对照通过。

## 怪群批量链路重构（2026-10-16）

用户已允许重构框架。本轮把重复的逐怪邻居计算改为“当前物理步统一规划 → 每怪真实身体移动 → 立即提交实时索引 → 实时攻击／弹射查询”。普通避让使用该步首次普通查询时的共同位置快照，每对邻居只计算一次原有精确力并向两侧分配；半邻格遍历不遗漏半径内同伴，不限制邻居数量。没有延用前物理步的力，也不保留动态挡墙结果。

索引是当前位置的提交入口：每次移动、外力、出生激活和体型／间距变化都即时 update，死亡、取消和退出即时 remove。物理步切换不会让未移动的位置自行过期。批量避让后的位置提交和 `nearby`／`swept_bodies` 继续实时；当步出生、移除、槽位复用、体型、间距或激活改变时，本步剩余避让恢复原逐怪计算，下步重建。未知半径查询也保留旧实现。实际墙体移动、碰撞体、导航半径、攻击频率和动画不变。

## 100 FPS 预算与第二轮链路筛选（2026-10-16）

目标继续按正式地图、128／160 五类混编、基础剑术与人物本体弹射、60 Hz 物理和约 100 FPS 验收，沿用当前真实相机、1280×800、Forward+／D3D12。纯 GDScript、完整动画／特效、怪群密度及实时碰撞标准不变。以下区分测得的当前架构成本、预算模型和尚未证明的优化空间，不把某个微测倒数称作游戏理论极限。

当前版本重新冻结 175 个运行时脚本归因：160 只普通身体 `move_and_slide` 约 125～126 次／步，插桩累计 3.04～3.21 ms；既有平地扫掠约 0.35～0.38 ms，批量避让一次约 1.25～1.33 ms。双侧通行检查约 58～80 次／步。函数计时是 inclusive，深层计时器、字典及包装本身增加开销；不能相加，也不能直接当作可节省的生产时间。Creature 的两层回调确有约 124 次重复战斗资格检查，但谓词自身很短，不能把插桩的 1.2 ms 全部归为收益。

预算模型以每秒为单位：设主线程每物理步成本为 P ms，每显示帧成本为 D ms，无法归入二者的固定成本为 C ms／秒，物理频率 H=60，则维持 F FPS 至少需要 `60P + FD + C ≤ 1000`；GPU 每帧成本 G 则另需 `FG ≤ 1000`。CPU 与 GPU 可重叠，不能把两者毫秒相加；各线程成本也必须先确认归属。P、D 必须是同一主线程上互不重叠的完整归属；当前脚本 physics／process 窗口只覆盖部分工作，process 窗口不等于完整 D，冻结整帧时间也不等于 D，绘制准备、服务器与同步须另行归属。忽略 C 的条件上限为 `F ≤ min((1000−60P)/D, 1000/G)`，这是测量成本保持不变时的乐观平均吞吐模型，不是硬件或 Godot 的绝对极限，也不保证每个尾帧都在 10 ms 内。P 的倒数不是游戏 FPS；未来异线程工作须单独约束各线程，不能把总 CPU 时间塞回 D。[Godot CPU 测量说明](https://docs.godotengine.org/en/stable/tutorials/performance/cpu_optimization.html)、[GPU 瓶颈说明](https://docs.godotengine.org/en/stable/tutorials/performance/gpu_optimization.html)。

### 首要发现：水域使陆地快路整体失效

运行时地形碰撞体有 12 个形状：一个含 3234 个顶点的三角面形状及 11 个水域阻挡形状。`_compact_collision_faces()` 遇到任一水格即撤销整张地图的 `_collision_is_flat`；`ground_collision_body()` 因而返回 null。正式开关虽开启，普通陆地怪物仍无法通过平地移动的支撑资格。

同一地形身体随后进入固定障碍集合，地面的 XZ 范围占据整个战区；共享证明没有可用的独立支撑体，导航通路、身体移动和射线也无法获得原先的空地快路。此处是新增局部水域触发了全图保守回退，并非只在水边多做检查。

轻量原生探针在 160 只样本中记录：

- `move_and_slide()` 约 159 次／物理步，累计约 2.92～3.25 ms／步。深层探针另确认普通追击尝试平地移动后大量回退；特殊招式和局部退步本就保留原求解。

- 完整普通追击 `chase_route()` 约 5.2～5.4 次／步，约 0.35～0.64 ms／步；批量避让规划约 0.42～0.58 ms／步。本轮稳定人口样本没有批处理回退，不能将此前小夹具的出生／移除回退直接称为当前持续瓶颈。

## 恢复含水地图的陆地快路（2026-10-16）

将地形原有三角面保留在 `Generated/Body`，每格水域阻挡盒移到独立 `Generated/WaterBlockers`。正式地图仍是一份原地形三角面和十一份同尺寸、同位置的挡水盒，仅增加一个静态身体，不填平河床、不增加地面覆盖碰撞或改变渲染网格。水域反弹继续按真实命中形状识别，导航只排除地形面，挡水盒始终参与真实扫掠。

陆地资格在生成时检查：所有旱地必须同高、无桥／坡道，所有河床不高于旱地；局部完整身体留宽仍须通过 TerrainPath 的地面证明。于是水池不再让整张陆地退回通用求解，也不再让地形的大包围盒占满固定障碍网格。贴水、复杂地形、悬空、外力和不确定障碍仍使用原有求解；不扩大快路到无法证明的区域。原有八格分块证明仍会保守拒绝含水分块中的部分旱地，这一局部回退没有取消。

已有障碍缓存只登记地形生成器本次完整创建的新身体，重新建立支撑范围和挡水占用，不重新扫描整个世界。外部原生修改必须先撤销，不能利用生成器入口重新认证旧身体。新增按身体反查的 Shape 订阅记录，身体移除后释放对应拥有者和资源引用，重复重建不积累旧几何；共享 Shape 在其他身体仍使用时继续被观察。

### 复杂度与空间换时间

设 M 为地形格数，V 为建表时读取的形状顶点数，A 为固定障碍包围盒栅格化的累计格访问数，G 为占用表外接矩形格数，K 为一次地面证明覆盖的八格分块数，D 为实时障碍数。固定表和地面证明由怪物共享，不按怪物复制。

| 工作 | 时间成本 | 缓存与失效 |
| --- | --- | --- |
| 陆地资格检查 | 重建时 O(M)，读取资格 O(1) | 地形重建重新检查；原生地面修改先撤销 |
| 固定障碍栅格／前缀表 | 建表 O(V + A + G)，矩形查询 O(1) | 身体／形状变动撤销固定项，按需重建 |
| 局部平地证明 | 冷分块每块最多扫描 8×8 格；热查询 O(K)，命中已证明矩形时 O(1) | 数据、范围、格尺寸、层高或地形变换变化失效 |
| 实时障碍守卫 | 每次至少 O(D)，另加各动态形状的包围盒计算成本 | 不跨查询缓存动态结果 |
| 未托管绑定复核 | 每物理步一次，O(被复核形状数) | 保留原有原生引用／margin 安全检查 |
| 重建后订阅释放 | O(移除身体拥有的唯一 Shape 数) | 反查记录 O(形状绑定数)，不扫描所有资源 |

当前正式地图的固定栅格为 34×34：1156 字节占用数组与 1225×4 字节前缀数组，共 **6056 字节，约 5.9 KiB**；另有 468 个稀疏占用字典条目、身体／形状记录及既有导航数据，不能把 5.9 KiB 当作整个系统内存。全图缓存以 O(G) 空间换取固定障碍范围查询 O(1)。这是复用已实现的表，不是本轮新分配了同规模的第二张表；新增反向资源记录为 O(形状绑定数)。当前绑定复核为 14 个身体／26 个形状，实时守卫为 1 个身体，均为加载时快照，运行中可变化。

固定表最大 65536 格，超过后沿用有面积上限的稀疏回退，不承诺任意地图都 O(1)。完整怪物更新也不是 O(1)：仍须推进每只怪的状态、动画、实际招式及局部避让。恢复快路主要削减“怪物数 × 每只查询次数 × 原生碰撞求解成本”中的最后一项，未改变整个系统按怪物数增长的基本关系。Godot 自有宽相位／窄相位，不能把原 `move_and_slide()` 简化为逐次 O(全地形三角形数)。

### 方法与边界

新增 `tools/benchmark_native_queries.gd`，加载正式 World 和独立地图战斗配置，仅在测试进程内复制人口资源、开启免伤锁血模拟、关闭选卡与声音。使用五种真实混编怪物、当前人物移动、真实基础剑术、蓄力预览和本体弹射；不修改生命、攻击间隔、动画、伤害距离、碰撞体、拥挤参数或正式成长配置。

每臂独立进程，固定 60 Hz 物理和 `--fixed-fps 60` 进程时钟，出生期间暂缓怪物物理并保存有序出生哈希，全部出生后预热 120 步。随后依次执行站立普攻 180 步、四方向移动普攻 120 步、持续蓄力 120 步及真实弹射 240 步。128 采用旧／新／新／旧，160 采用新／旧／旧／新。每组内使用同一源码快照、种子、出生计划和输入步骤；不同候选系列的绝对耗时和行为基线不拼接使用。使用 Godot 4.7.2 编辑器可执行文件运行脚本，未测试 Release 导出版本。

全原生开关还会影响障碍场节点是否建立，且当前拥挤择向使用对象 ID。完整后端的轨迹／CPU 差值不能直接当作某个函数的自耗时，也不能仅凭出生位置相同就假定逐帧行为相同；墙体检查始终针对各臂实际运动。最终采用的纯查询方案保留身体移动和障碍场，其行为另与旧基线比较。

同时记录三个窗口：

- `physics_callbacks_ms`：物理帧信号至末端 Node 物理探针。
- `physics_span_ms`：物理帧信号至后续进程帧信号，补上回调之后的物理服务器推进及消息处理；不包含信号之前的同步等全部引擎工作。
- `process_callbacks_ms`：进程帧信号至末端 Node 进程探针，包含真实蓄力预测、角标和显示数据更新。

下文流程指标为每阶段「一个物理窗口均值＋一个进程回调窗口均值」，再按上述步数加权。它是 **headless 中指定流程的 CPU 窗口指标**，不是整帧、显示 FPS、GPU 耗时或所有玩家输入比例下的收益保证。物理回调、较宽物理窗口不能重复相加；各自 P95 也不能相加当成整帧 P95。诊断用的两两间距和 3 mm 胶囊内部碰撞查询不计入回调窗口，执行诊断／输入准备的较宽物理窗口另行排除。

每 30 步检查存活数量、五种组成、控制器和战斗时钟、3 mm 内胶囊与实时墙体、个体间距及真实移动；同时检查实际蓄力／预览／发射、基础剑术与飞行命中、怪群转向、模拟免伤和关闭拨怪。每 30 步采样不能代替逐帧碰撞证明或人工手感验收。

### 为什么低阶算法仍然贵

一轮 128 只旧策略的蓄力段，在 120 次更新内记录到 30342 次 `Terrain.ray_clear` 请求，约每次 253 次；其中 10740 次由脚本证明短路，19602 次仍回退到原生射线。这不包括身体扫掠、其它形状查询及测试工具自己的独立诊断。

普通追击已使用空间网格和共享路径，问题不能概括为「缺少空间划分」。每次空地证明仍需要边界、形状绑定和实时动态障碍检查；证明失败还要继续执行原生查询。复杂度阶数没有表达这些常数、调用次数和重复检查。蓄力还要建立可见相连怪群及轮廓，纯进程回调窗口在初筛中达到约 9～14 ms；其中包括其它进程节点，不能全部归给一个函数。

CPU 稳定实时运行还必须满足预算：`物理频率 × 每步CPU成本 + 绘制频率 × 每次进程CPU成本 + 其它主线程成本 < 1000 ms/秒`。目标 100 FPS 的 GPU 每帧也必须低于 10 ms 并留余量。这里测到的窗口尚不完整，不能用它们的倒数宣称实测 FPS 或不可突破的硬件上限。

#### CPU 函数级采样与删减诊断

Godot 本地 `scripts` profiler 在预热后按阶段分别启停。128 只普通普攻段，怪物 `_advance_wave_step()` 的包含子调用耗时约 12.7 ms／步，其中普通 `_move_combat_body()` 约 5.2 ms、`_pursuit_crowd_direction()` 约 2.7 ms；后者包含避让与侧向通行检查。蓄力的 `predict_path()` 约 8.9 ms／次，其中外沿判群约 4.0 ms，回退短弧的群体区域计算约 2.9 ms。它们有嵌套关系，**不能相加为总耗时**。采样器有额外成本，原生 API 时间也会记在脚本调用者中；`super` 包装层的自耗时归属出现重叠，故不使用自动百分比宣称脚本占比或 GDScript 已到极限。

不启用 profiler 的额外诊断：

- 使用相同正式输入但仅关闭路线提示，128 蓄力窗口从约 23.2 ms 到 16.5 ms，实际蓄力、弹射和剑术仍运行；这一单组删减显示整个预测链路值得优先处理，不是承诺能无代价省下全部差值。正式提示未关闭。
- 独立夹具中保留 AI、直接线性移动而省略普通地面／碰撞求解，普攻约从 16.0 ms 到 10.7 ms；它会穿墙，**仅用于定位，绝不能接入玩法**。停止怪物物理模拟则普通段约剩 3 ms，行为显著改变。这两组说明 CPU 计算本身已足够昂贵，不依赖 GPU 光影才能出现瓶颈。
- 停掉怪物及 Sprite 的显示更新约省 2 ms 左右，同样只是上限诊断。动画没有被默认停用；它也不足以替代对普通模拟的改造。
- 试过实时原生体积查询替代空地证明的移动原型，收益只有约零点几毫秒，没有选为正式替换方案。只换一种物理查询入口仍不足以大幅提速。

删减实验的运动、命中、目标分布可能改变，不能把它们当作优化结果，不能跨夹具相减成精确模块成本。上述证据共同支持：当前 CPU 主线在逐怪移动／拥挤／通行链路，蓄力另有一份重复判群开销；关闭光影主要面向另一条渲染链路。
