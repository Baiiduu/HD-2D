# 四境 · HD-2D（three.js r170）

此目录为保留的 Three.js 视觉对照，正式游戏位于 `../../demoWithMeowa/1`。`node_modules/` 是可重新安装的本地依赖，不作为项目产物保存。

《仙门灯会·异变》当前为石板广场、六个人物、三盏简单占位灯与三层宗门山谷远景，用于检查铺装、材质、光影和背景构图。石板有固定明暗差异，稀疏叠加 Meowa 的裂纹、磨损、花瓣、水迹、青苔与污渍。冷色全局光与环境光、暖色占位点光、真实阴影、距离/高度雾和灯光体积散射已接入。地表、角色和分层远景使用 Meowa 美术。原四境夜景继续作为视觉基准保留。

- 引擎：`three@0.170.0`，后处理用 `postprocessing@6.36.4` 和 `n8ao@1.9.4`，构建用 Vite 5
- 美术素材：运行与构建读取当前目录的 `public/`，不再依赖外部素材目录。已有共享素材和道具已原样复制，来源、尺寸与 SHA-256 见 `assets/asset-catalog.json`。广场与远景来源见 `public/opening/provenance.json`。天空和雾使用 shader，广场远景使用原生 Meowa 图集；原四境的程序化远山与粒子保留。
- 这是早期 Three.js 环境原型，仅作效果实现对照；当前 Godot 玩法以[设计文档](../../docs/rpg-game-design.md)为准。原型素材来源见[实现与美术来源](assets/opening-environment.md)。

## 运行

需要 Node.js 18 或更高版本（开发时用的是 Node 24）。

```bash
npm ci              # 按 package-lock.json 恢复依赖
npm run dev          # 打开 http://localhost:5199
```

默认页面打开石板广场光影试验。`/?scene=benchmark` 打开原四境基准；截图模式也继续使用原四境。新光影使用独立保存位置，第一次进入时沿用旧广场中已保存的镜头和地表参数，应用新的光影默认值；原保存配置保留。

面板底部的“远景构图”可切换到较开阔的观赏镜头，不自动覆盖保存配置。“天空与远景”可调背景高度、距离、亮度与宗门灯火，并逐项恢复。远景为分层 2.5D 背景，图中瀑布与云雾为静态美术；广场与山谷边缘的地形过渡尚未制作。

`npm run map:opening` 从 `src/opening-layout.js` 重新生成第一块布局；`npm run assets:opening` 从已下载的 Meowa 最终文件重新复制运行资源，不调用生成服务。日常启动无需这两个命令。

操作：**WASD / 方向键** 移动（广场 3.2 m/s，原四境 4 m/s）。玩家可在广场内游走，有 NPC 碰撞，不能走出广场边界。按 **F2** 开关视觉面板。

生产构建：`npm run build` 生成 `dist/`，然后 `npm run preview` 在 http://localhost:5198 打开。

## 实时视觉调节

运行页面右上角有“视觉调节”面板，点击按钮或按 **F2** 展开、收起。滑块和数值输入即时生效，面板输入不会触发角色移动。

每个参数旁都有“恢复”按钮，只恢复该项的原始默认值，其他参数不变；单项恢复后需要点击“保存本地”才能在刷新后保留。按钮悬停提示默认值。

左上角显示实时 **FPS** 和平均帧间隔（ms），约每秒更新，收起面板后仍可查看。统计使用实际经过时间，不受游戏逻辑时间限幅影响；切回页面后重新采样。平均帧间隔包含浏览器调度与渲染等待，不是单独的 GPU 耗时。

- **石板与覆盖细节**（广场）：单块明暗幅度与裂纹、磨损、花瓣、水迹、青苔、污渍数量；数量 0 关闭该类，调节后位置保持固定。
- **光源方向与占位灯**（广场）：全局光方向、俯角和阴影；三盏占位灯的颜色、强度、范围及阴影。阴影 0 关闭、1 开启；灯光强度 0 同步关闭实际光源、间接光与空气散射。
- **色彩与后处理**：曝光、亮度、对比度、饱和度、色温、冷暗暖亮染色、泛光强度与阈值、暗角。
- **雾与大气**：雾色、距离雾密度、起雾距离、低处雾密度、高度衰减、基准高度、灯光空气散射。
- **天空与远景**：天顶与天空中部颜色、地平线辉光、星光与银河强度、远山底色与雾化。
- **全局光与环境光**（原四境为“环境光与月光”）：方向光、环境光及地面反弹光的颜色与强度。
- **景深与接触阴影**：景深模糊半径、远景模糊比例、接触阴影强度。
- **镜头**：视野角度、俯角、跟随距离、横向旋转（−180°～180°，绕玩家转动，第一块环境默认 22°）。每项独立恢复，均支持本地保存与 JSON 导入导出；旧配置缺少旋转参数时使用当前场景默认值。

“保存本地”将参数存到当前浏览器，刷新后自动恢复；“导出 JSON”和“导入 JSON”用于保存、分享或恢复配置。“恢复默认”还原原始画面，并清除当前浏览器的已保存配置。导入只应用当前画面，需要再点击保存本地才能在刷新后保留。

浏览器保存按站点地址区分，开发和预览端口之间可通过 JSON 迁移。参数不会自动写回源文件。核心控制器为 `src/art-direction.js`，天空、雾和调色使用实时 uniform；水面与地面的反射视图同步使用当前雾参数。

截图模式自动隐藏面板并使用原始参数，避免本地保存影响基准截图。普通运行可使用 `/?visuals=0` 隐藏面板并使用原始参数。

## 截图模式（无需人工操作）

```bash
npm run shots        # 5 张全截，保存为 screenshots/shot_*.png（1280×800）
npm run shots -- 4   # 只截第 4 张
```

`scripts/screenshots.mjs` 会做这几件事：
1. 启动 Vite；
2. 通过 `playwright-core` 调用本机已装的 Chrome 或 Edge，以 GPU 无头模式运行（ANGLE/D3D11），不需要另外下载浏览器。路径不同时用环境变量 `CHROME_PATH` 指定；
3. 打开 `/?shots=all`。

页面会把玩家放到指定坐标，高度取该处地形，镜头直接对准。等 150 帧，让镜头、粒子、阴影和反射都稳定下来，再从 canvas 取 1280×800 的 PNG，通过 dev server 的 `/__save-shot` 写入 `screenshots/`。

## 代码结构

| 文件 | 内容 |
|---|---|
| `src/layout.js` | 解析布局；地形格、坡道、水流方向；地图外的程序化边缘地形；高度查询与碰撞 |
| `src/terrain.js` | 地表、崖壁、远景大地的几何体；地形 shader（区域底材、dual-grid、积水、AO） |
| `src/props.js` | 布局中的建筑和道具几何体，以及各自的程序化材质；木桥 |
| `src/water.js` | 水面（flow map、岸边泡沫、反射）、瀑布 |
| `src/lights.js` | 点光、聚光、光源光晕、街灯光锥、点光阴影分配 |
| `src/sprites.js` | Y 轴 billboard 角色、接触阴影 |
| `src/particles.js` | 萤火虫、瀑布水雾与水花、灯下浮尘 |
| `src/sky.js` | 夜空、分层远山 |
| `src/reflection.js` | 平面反射（地面一层，两种水面高度各一层） |
| `src/post.js` | 后处理：N8AO → 灯光散射 → 移轴景深 → Bloom → ACES → 调色 → 暗角 |
| `src/shaderlib.js` / `src/materials.js` | 通用 GLSL：像素采样、全局雾、自发光间接光、材质补丁 |

## 自评

以下技术自评与硬件数据来自原四境基准；第一块环境的当前范围与检查结果见 `assets/opening-environment.md`。

### 实现了哪些效果、用什么技术

1. **像素质感**
   - 所有贴图和角色都用"像素抗锯齿采样"（`texPixel`）。放大时每个纹素仍是硬边方块，只有纹素之间的过渡被压缩到约 1 个屏幕像素并做抗锯齿，所以镜头移动时不会闪烁。缩小时用 `textureGrad` 配合三线性 mipmap 加各向异性过滤。
   - 角色是 64×64、高 1.5 m 的四边形，只绕 Y 轴转向镜头。用 alpha-to-coverage 配合 4× MSAA 得到干净的轮廓，阴影用自定义深度材质，遵循 alpha。
   - 玩家行走时有轻微起伏和挤压，左右移动会水平翻转精灵。
   - 程序化细节（砖缝、瓦片、窗棂、面板灯）都对齐到 40 px/m 的像素网格。

2. **地形过渡（dual-grid）**
   - 在地形 shader 里逐像素计算：取显示格四个角的地形格，算出 key，再查图集瓦片。图集 tile 内的采样坐标被钳住，梯度取连续的世界坐标，所以没有接缝和 mip 串色。
   - 叠放顺序是底材 → 泥土 → 道路。路面会跟随坡道的高度。
   - 不同区域的底材交界用像素化噪声抖动，不是生硬的直线。

3. **分层高差**
   - 每对相邻格比较共享边两端的角高度，在高的一侧生成竖直崖壁，坡道两侧会生成三角形侧壁。
   - 崖壁用 `cliff_rock_strata` 贴图，水平方向沿墙面平铺，竖直方向按世界高度平铺。
   - 崖顶有用上层底材画的锯齿状草沿，草沿下是一道暗线；崖顶受光提亮，越往下越暗，墙脚有接触 AO。
   - 地面也会读取周围格子的高度，在崖脚处变暗。

4. **主光与阴影**
   - 月光方向、颜色取自布局，强度按画面效果放大。
   - 4096 分辨率的 PCF 软阴影，阴影视锥跟随镜头，并对齐到纹素避免抖动。
   - 接触 AO 由三部分组成：N8AO 屏幕空间 AO（半分辨率加去噪）、建筑和台基 footprint 的解析 AO、角色脚下的软阴影斑。

5. **光源的完整表现**
   - 每盏灯都有发光本体（带窗框、纸罩肋条、闪烁的程序化灯罩）。
   - 空气中的光晕有两层：前置的 HDR 光晕 billboard，以及后处理里对每盏灯解析求解的单次散射。后者是沿视线对 1/d² 的闭式积分，并按深度裁剪，所以会被前方的物体正确遮挡。街灯额外加了雾密度。
   - 地面光池来自真实的点光和街灯向下的聚光，街灯下还有可见的体积光锥和浮尘。
   - 湿润地面上有平面反射倒影：按材质区分湿度（鹅卵石 / 金属 / 青石板 / 积水坑），按粗糙度取 mip 模糊，加法线扰动和 Fresnel，并压低夜空薄雾的反射、突出灯光。

6. **间接光**
   - "自发光 GI"：每条霓虹灯带、每扇窗和每盏灯都作为线段或点光源，以 wrap 漫反射的方式给周围的地面、墙面、角色和瀑布加上一次反弹光。赛博区地面会被青色和品红映染，窗前路面是暖色。
   - 青色 / 品红补光、灵光、林间光这几盏布局灯照常照明，它们产生的散射光晕被压得很低。

7. **大气与纵深**
   - 替换了 three.js 全局的 fog chunk：指数距离雾加解析高度雾（Quilez 公式），近处偏暖、远处偏冷紫。所有材质，包括反射图和半透明物体，都用同一套雾。
   - 地图外一圈 10 格是程序化生成的台地，同样用 cell 体系和崖壁。道路沿平坦谷地一直延伸出去；溪流向北逐级跌落成小瀑布，源头是一处从高台流出的泉。
   - 再往外是起伏的远景大地，变暗、去饱和后溶进雾里。
   - 最远处是三层程序化山脊，做了空气透视；天空在地平线处与雾色衔接，上方有星空和银河。

8. **水**
   - 水面用 `water_shallow` 做双相位 flow map，沿每格的流向流动（河道拐弯处也会转向）。
   - 岸边有像素化、会闪动的泡沫，瀑布下方是湍流泡沫，水面有反射。
   - 瀑布是弯曲的薄片，按列以不同速度下落；顶部和底部有泡沫，受灯笼光照。底部有体积感的水雾粒子和弹跳的水花。

9. **点缀与后处理**
   - 萤火虫（随机游走、闪烁、HDR 发光），灯下浮尘，草地上的风浪明暗。
   - mipmap Bloom（阈值约 0.95）。
   - 自写的移轴景深：近景强模糊，焦平面附近约 7.5–17 m 保持清晰，远景轻微模糊，近景的模糊范围向外扩张。
   - 之后依次是 ACES 色调映射、调色（暗部略冷、亮部偏暖、轻 S 曲线）和暗角。

10. **整体**
    - 色调中性偏暖：暖色的灯、窗、灯笼，对比青色和品红的霓虹，以及偏冷的远景雾。
    - 画面亮度保证可读，没有大面积死黑或过曝。

### 没做到或做得不够好的地方

- **镜头 FOV**：题目要求 25°，布局 JSON 里的 `camera.fov_vertical_deg` 是 30°，我按题目用了 25°。
- **shot_4 的机位 (22.4, 2.5)**：这个坐标落在河道格 (14, 2) 里，河床层级是 -1。按"高度由地形决定"，玩家站在河床上，看起来像在水里涉水。我没有把他挪到别处。
- **远景天空的面积**：俯角只有 10°、FOV 25°，画面顶边只比地平线高约 2.5°，天空几乎露不出来，远景主要靠雾、远山和外围台地撑。远山被下半部的雾托着，有时看起来更像低云。
- **地图外围的地形**：地图外一圈台地、延伸出去的道路、外围那段溪流（逐级小瀑布和源头的泉）都是我额外生成的远景地形，不属于布局；没有加任何建筑或道具。布局里"外缘向下延伸到 -2 层"的裙边被这片连续的外围地形取代了：地图边缘直接连到外围台地，所以没有单独生成那段裙边。
- **点光阴影**：WebGL 的纹理单元有限，只有离玩家最近的 4 盏标记了投影的点光会实时投影，其余只照明不投影。
- **平面反射**：只做了三层（地面 y=0.02，以及两种水面高度）。高地（1、2 层）上的地面没有反射，好在那里基本是草地。反射不包含屏幕空间散射光晕，但包含光晕 billboard。
- **散射光晕**：只靠深度裁剪，没有真正的体积阴影，所以灯杆不会在光晕里投下暗束。
- **对布局几何的调整**：
  - 殿宇的飞檐是对布局给定的 `RoofEaves` 盒子做角部上翘的顶点变形，占地不变，但形状和原盒子略有不同。
  - 修仙区的灯笼在布局里是暖白色材质，我按题目描述画成了红色纸灯笼，它发出的光仍用布局里的颜色和强度。
- **近景景深**：布局把部分 NPC 放在离镜头只有 3–4 m 的地方。为了移轴微缩感，近景会被模糊，这些 NPC 的像素边缘因此不再锐利，这是有意的取舍。
- **光照强度**：Godot 的光照和自发光强度是凭目测换算的（点光约 ×2.4，自发光约 ×1.25）。

### 帧率与测试硬件

- 硬件：NVIDIA GeForce RTX 3050（Windows 11，D3D11 / ANGLE），Intel Core i5-13400F，64 GB 内存，Chrome 无头 GPU 模式。
- 1280×800 下，5 个截图机位大致在 **55–70 fps**。河流附近会额外渲染两层水面反射，各机位读数有波动。
  - 主要开销：3 次平面反射、4 张点光立方体阴影加 4096 月光阴影、N8AO、28 采样景深。
  - 早期版本还没有水面专用反射，景深采样也少，当时测到约 85–95 fps。
