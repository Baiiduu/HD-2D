# 第一阶段：体验拆解与资源盘点

状态：初始准备与讨论记录。用户随后授权按参考方向制作第一块 Meowa 美术与白盒环境；当前成果、来源与检查结果见 [opening-environment.md](opening-environment.md)。以下保留当时的盘点与讨论依据，不作为当前完成状态。

## 从体验倒推需求

已经确定：像素风 HD-2D、《仙门灯会·异变》的世界与事件结构，以及保留当前 three.js 的光影、大气、水面、后处理、视觉参数单项恢复和帧率显示。

建议第一阶段先回答：**玩家能否看懂灯会原本的生活状态、异变造成的变化，以及自己的行动带来的恢复？** 先共同确定一个代表性画面和对应资源清单，再制作场景。第一阶段具体范围仍需讨论。

| 体验需要表达什么 | 因此需要的资源类别 | 还需要讨论什么 |
|---|---|---|
| 这是一个东方幻想宗门的灯会 | 建筑、地表、灯会物件与背景 | 主要画面在哪里、建筑风格、灯会特色、构图 |
| 玩家与居民让世界有生命力 | 主角与 NPC 图像、相应动作 | 角色外形、画面比例、首批动作与人数 |
| 异变让同一地点发生明显变化 | 可改变状态的光源及必要的视觉、声音资源 | 哪些变化最重要；哪些由现有渲染实现，哪些需要新增素材 |
| 玩家行动能让环境恢复 | 可交互对象、状态表现、反馈资源 | 对象外形与操作方式，不预设灵石、符文或具体机关布局 |
| 玩家理解当前状况和操作 | 必要的文字、图标、界面和声音提示 | 第一阶段需要多少 UI，采用什么视觉语言 |

灯光、雾、色彩、反射是已有表现能力，不必为每个效果单独生成图片。地图布局数据与地表、建筑、道具素材也需分别考虑；一张好看的整图不自动具备可行走空间、遮挡关系或可交互物体。

## 已归档资源

已原样复制 **46 个文件，其中 42 张图片**。包含来源图、参考图和元数据，不能把这个数量当作 42 个已经可用的游戏资产。

| 类别 | 已有内容 | 目前能确定的用途与限制 |
|---|---|---|
| 角色静态图 | 8 张 64×64 PNG | 可用于原场景与候选外观讨论；没有动作帧。修仙角色也尚未选定为正式主角或 NPC |
| 地表及材质 | 7 张 64×64 PNG | 现有程序已使用；是否适合新场景由风格讨论决定 |
| 地形图集 | 2 张 256×256 PNG | 原场景道路与泥地过渡可用；不等于新地图布局 |
| 道具组件 | 19 张 PNG，尺寸不一，题材混合 | 包含树木、石块、灯笼、门及现代/赛博物件；需要检查像素密度、透视与角色比例，不能整包直接接入 |
| 补充地表参考 | 4 张 64×64 PNG | 仅作为候选参考，尚未接入新场景 |
| 来源图 | 2 张角色/道具整图 | 用于追溯和预览，不由运行入口加载 |
| 布局与说明 | 原场景布局、地形说明和来源元数据 | 支撑现有基准场景与来源追踪；没有用户确认的新地图 |

在本次检查的共享包和 Godot 素材目录中，未发现正式的角色动作序列、UI 素材包或音频文件。现有角色起伏、缩放和粒子运动是程序效果，不作为已经具备角色动画的证据。灯笼图片是否需要亮灭两套素材，应根据最终渲染方式决定，不能提前断定。

完整文件级清单见 [asset-catalog.json](asset-catalog.json)，包括尺寸、来源路径和 SHA-256。道具裁切信息见 [prop-components.json](prop-components.json)，来源整图在 `source-packs/`。

## 接下来先沟通的事项

1. **首个代表性画面**：希望玩家第一眼看到的场所与主体是什么？宗门广场、石桥河岸等都是总体设计中的候选，不在这里默认选定。
2. **统一的美术基准**：以哪些现有画面或参考作为标准？共同确定角色比例、像素密度、建筑与灯会物件的风格。
3. **最小资源清单**：根据该画面列出需要的地表、建筑、道具、角色和动作；逐项判断复用、修改或新增，再确定声音与 UI 的首批需求。

以上沟通完成后再落实素材和场景。暂不确定地图尺寸、摆放坐标、资产数量、角色身份或机关操作，不调用 Meowa 生成资源。

## 资源导入与目录

- `public/`：运行时静态资源，Vite 开发与构建均使用这里的本地副本。
- `assets/`：来源图、目录清单与元数据。
- `scripts/import-existing-assets.mjs`：原样复制已有资源，检查哈希；遇到目标文件内容不一致时停止，不覆盖。
- `experiments/m1-event-draft/`：未确认的事件实验，已移出默认入口，不作为场景方案。

需要重新同步已知资源时运行 `npm run assets:import`。源目录可通过 `--shared-dir` 和 `--demo-dir` 指定；日常运行不需要外部目录。原始外部资源未修改。
