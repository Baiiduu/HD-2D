# 已确认方向基准的动画制作与接入

用户已确认：原始斜正面 front、CALL032 侧面（左右镜像）、CALL030 Back15；要求分别制作待机与跑动并接入 Godot。本阶段不再请求同一范围的确认。

采用 Frame Animation V2 直接从已确认站姿制作动作，避免新增独立跑姿重绘。每种 8 帧、1 秒循环、Pixel/480p/Detailed，保留头型与身体比例，待机仅轻微呼吸，跑动为小步原地轻跑。先生成正面跑动并检查，之后扩展其余动作。

为避免此前 V2 透明片残影，先保留纯灰背景动画，检查通过后使用 Meowa 像素高级去背景。来源统一为 64×64，V2 居中 padding=16，目标 80×80；Back15 先去背景，再裁掉已有透明边距得到原生 64×64，像素不缩放。正式动作仍以实际输出尺寸和逐帧检查为准。

六种运行槽位：idle/run 为侧面，idle_front/run_front 为原图斜正面，idle_back/run_back 为 Back15。待机 8 FPS，移动基准 4 m/s 时跑动 12 FPS，沿用现有按实际位移调速逻辑。左侧仅 flip_h 镜像，不独立生成。

每种检查全部帧：方向、头型/耳机/脸型、头身比与衣长腿长、像素尺度、完整透明轮廓、动作幅度和循环衔接。通过后才替换对应正式槽位；原始产物和失败、未采用版本全保留。像素尺寸统一只使用透明补边和原生切帧，不重采样角色。

接入前另存本轮开始时的 runtime 备份和来源映射。替换完成后运行 Godot 导入、无界面与真实渲染的四向验证，检查停止朝向、斜向、左右镜像、碰撞以及倒影。地图、相机、光影与玩法保持现有状态。

所有调用继续归入任务 4，不新增任务序号；每次调用前保存完整参数并登记固定页面，调用后保存真实返回和质量检查。
