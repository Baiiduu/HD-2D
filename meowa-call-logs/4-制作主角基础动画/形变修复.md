## 原因与检查方式

- 形体差异已经存在于 Meowa 原始素材，不能归因于 Godot 渲染。
- 起始跑姿单独编辑，衣身与头部轮廓发生变化；随后动画增加较大抬腿和腾空，部分帧可见腿长明显缩短。单帧身体宽度变化需区分正常摆臂和衣身变形。
- 原提示词没有明确锁定身体比例，返回的优化提示词重点是动作与上下弹跳。
- 相同画布尺寸、透明补边、统一缩放与 FPS 均不等于形体比例固定。修复需从参考图和动画内容入手。
- `compare_proportions.py` 将站姿仅补透明边距，与编辑起始帧和所有动画帧按原像素尺寸并排。没有缩放正式素材。`proportion-review.json` 的 head_top_region 是以黄色衣服起点划分的辅助区域，不是精确解剖分割，不能单独作为质量通过标准。

## 修复对照

CALL017 核对 V2 帮助。CALL018 直接使用 CALL008 正面站姿，绕过单独跑姿编辑，生成小幅慢跑对照：pixel、480p、medium（精细）、16 帧、loop、alpha sharp、standard 去背景、每批 4 帧、灰底 #c6c6c6、提示词优化、中心 padding 8。

提示词原文：

```text
这个黄衣青年保持正面朝向，小步原地慢跑，双腿交替，手臂小幅摆动，完成一轮后回到起始站姿。固定镜头，保持原图的头部、耳机、躯干与四肢比例，不弯腰，不改变人物大小。
```

产物需再检查固定部位比例、动作幅度、像素尺寸、脚底落点、首尾衔接及透明边缘。仅通过后才替换；切换 V2 本身不保证比例一致。

CALL018 接口成功，但 V2 透明原片有纵向衣服残留，未采用。对应带背景原片无此残留；按 WebP 规范抽查原始 ANMF 图像数据也含残留，排除仅由本地解码合成导致。CALL019 核对独立去背景参数；CALL020 使用带背景原片与实测灰底 #c3c3c3（各帧左上角均 RGB 195）进行 Meowa 像素高级去背景，16 帧透明产物消除了残留。V2 返回 72×72；padding=8 是此路径的整体补边量，不能当作四边各 8。

用户随后指出正面脸偏宽。CALL022 以正面站姿和原角色为参考，先试修脸颊两侧各收窄一个原始像素，保留头发、耳机和身体大小。前后比例问题仍需继续处理，不能以去背景成功代替比例修复。

CALL022 返回图转为三分之四侧面，身体也变窄，质量未通过且没有接入。CALL023 只使用正面站姿作为唯一参考，明确保留正面朝向并仅修改脸颊。

### 脸型与动画比例修复接入结果（CALL017～CALL028）

本轮新增 12 次真实 CLI 调用，接口均成功；不等于 12 份素材全部采用。旧动画实际使用 animate-run / pixel-engine-v1.1，并非帧动画 V2。形体差异已存在于原始生成素材。

CALL018 的 V2 透明片有衣服残留，未采用；CALL020 去背景消除了残留，但该动作没有作为正式版本接入。CALL022 修脸转成侧面、CALL023 脸更宽，均未采用。CALL024 使用 image-edit-run 的 image-2.5 / pixel / strict / ultimate 选项，保留正面站姿并收窄脸颊、下颌；作为本轮正面参考。

正式替换：CALL025 左右跑动、CALL026 背面跑动、CALL027 正面跑动、CALL028 正面待机。修帧使用 animation-edit-run / pixel / generation-speed normal / advanced 去背景，并传入对应站姿参考。像素未经整体缩放或本地重绘；采用工具声明的 640×80 PNG 横向帧图，以原生 80×80 切帧。部分返回 WebP 有残影，因此正式 PNG 和预览 WebP 都由清洁帧图准备，不声称是原始 WebP 字节副本。

正面待机源第 0 帧仍是旧宽脸，第 6、7 帧较宽；正式采用零基序列 [1,2,3,4,5,4,3,2] 组成呼吸循环。保留原始失败/未采用产物、完整请求及优化提示词。整项任务累计 28 次：26 次接口成功、2 次早期依赖失败。模型、种子、费用只按实际返回记录，没有费用推算。

Godot 无界面和 D3D12 Forward+ 两次验证各通过 14 项，0 失败；实际检查了正背面待机和跑动、左右镜像、停止朝向、碰撞及倒影。技术通过不代表所有生成帧在美术上逐像素一致；跑动仍有动作引起的轮廓变化。
