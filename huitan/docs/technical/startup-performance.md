# 游戏启动性能排查

## 当前准备流程

正式 World 的隐藏入场预热抽取穿雾、到位与散雾的四个状态，每个等待两次真实绘制，随后恢复正常相机并再绘制两帧；同时等待导航、战斗反馈对象池及菜单战斗反馈准备器完成。预热不按完整 8.2 秒演出计时，点击开始仍播放完整入场，并复用当前 World。

画质页在地图 Style、天气等延迟绑定后的同轮延迟队列中完成初始化并应用本机覆盖，不再主动等待两个绘制帧；内嵌菜单与游戏内入口共用地图入口捕获的默认值，恢复默认不会把已应用的本机配置误当作场景基线。无界面测试仍默认隔离本机存档。

所有必要预热完成后，主菜单暂停主视口的 3D、地图全屏后处理，以及水面反射和极光的附加视口绘制；保留地图实例、物理、天气／极光时钟和菜单演出。开始前恢复进入菜单前的绘制状态，附加视口按最新画质选择继续。菜单内修改画质或窗口尺寸会临时恢复绘制，从最后一次变更再等两帧后收住，不重建地图、导航或反馈池，不重复隐藏入场。开始确认过程中也遵守这个就绪门槛；退出组件归还原状态。这部分主要减少菜单驻留的无效绘制，GPU 耗时和加载时间收益须由实机计时确认。

### 菜单内战斗反馈准备

`scripts/world/combat_feedback_warmup.gd` 按当前 World 的实际资源和开关分帧准备，开始按钮在所有任务完成、再经过两次真实绘制后才开放。CPU 调度预算约每帧 6 毫秒，减少准备队列的跨帧等待；单个任务不可中断，不能将该预算理解为帧耗时上限。返回主菜单保留已完成状态，不重复准备。

| 范围 | 菜单中准备的内容 |
| --- | --- |
| 人物动作 | 蓄力圆弧、聚点、聚力风、瞄准路线节点；飞行残影、气流、地火及火星；闪身残影池 |
| 反弹与剑术 | 碰墙帧、火花、贴面扩散、出射气流；正式普攻／飞行剑光及消散余迹的网格和材质 |
| 怪物反馈 | 原有死亡与接触池、死亡材质变体、吐籽弹丸储备；共用招式预告、出怪剪影图集和按当前地图容量预留的实例缓冲 |
| 局内技能 | 只遍历当前可用技能，建立奔雷、贯穿、棱光和镜印等已登记实现的闲置表现池；不学习技能或发起攻击 |
| 成长与 UI | 隐藏的经验宝石外观载体；沿用伤害数字储备，准备数字及真实界面字形、开场／清波各自字号和现有 Canvas 材质 |
| 声音 | 实际核心音库、脚步和 UI 音库、技能音源、循环声副本、天气及曲池音源；独立解码短缓冲后丢弃，不连接播放节点或音频总线，遵守地图旧音源排除清单 |

准备直接复用各组件的实际构造入口和闲置池，不模拟命中、死亡、刷怪、经验收取或开战，不消耗出怪与成长使用的全局随机流。怪物场景只读取资源与帧，不实例化 AI。经验外观载体不登记到真实拾取列表；隐藏载体在 World 销毁时一起清理。储备量覆盖首次使用，后续大量并发仍可按原规则扩容，不预分配整个无尽模式。

四种人物遮罩共用 `scripts/rendering/sprite_body_layout.gd` 的原生顶点／UV 缓存，归实际 Sprite 所有；菜单预先准备已配置人物帧及水平镜像。普通压缩贴图与 ImageTexture 按画布、区域、像素尺寸和翻转等真实布局共享缓存，同布局换帧不重复创建取样卡或向渲染服务器读回。图集及其它特殊纹理仍保留资源身份与区域映射，人物位置和姿态仍实时同步。避免残影、地火、聚力风和飞行气流分别读取同一布局，不改变原生像素或裁切间隙。

三维反馈保留真实网格与材质的隐藏实例。Forward+／Mobile 的管线准备可由这种实例触发，单独加载 Shader 不能替代完整组合的准备；实际覆盖仍须查看目标显卡上的管线编译监视器。[Godot 管线编译说明](https://docs.godotengine.org/en/stable/tutorials/performance/pipeline_compilations.html)

`tests/test_combat_prewarm.gd` 验证菜单就绪门槛、池复用、开场／清波字形、无假战斗／掉落／声音、全局随机流隔离及重复调用；其无界面报告的 `body_layouts=0` 是刻意跳过渲染读回，不代表图形路径已验证。动作、剑术、技能和菜单往返沿用对应回归。人工待验收：全新 F5 后第一次蓄力松手、首次碰墙、首次命中／群杀、首次技能和清波，以及返回菜单再次开始。记录真实帧耗时与管线编译数，不能从无界面准备时长推断 FPS 或宣称首次卡顿已经消失。

### 地表与入场准备

自由手绘地表改存为 `data/world/world_surface.res`，与笔刷共用同一份 Godot 原生压缩数据。迁移保留 UID、36 块半浮点像素数据、172 个铺装对象及其顺序和坐标；笔刷保存继续使用无损压缩，不维护独立运行缓存。原始数据约 20 MB，压缩后约 176 KiB。已同步场景、工具及数据保护测试的引用。

此前两次无界面测量，从诊断脚本开始至开始按钮就绪约由 13.6–14.0 秒降到 4.07–4.14 秒；该样本早于本次扩大反馈准备范围，不能作为当前菜单总耗时。正式演出时长与画质配置保持。这些数值不包含显卡首次绘制和编辑器拉起进程的开销，实机首帧及点击开始后的衔接仍由人工在正式场景验收。

`test_world_entry` 覆盖逐绘制状态、长帧、取消、目标销毁及正式播放恢复；`test_surface_storage` 覆盖压缩、半浮点字节、铺装顺序、UID、笔刷再次编辑保存和正式场景绑定。主菜单、返回菜单、战区、水池与湿地面另沿用对应的无界面回归。

以下保留早期区域检索优化的背景与测量，不能直接套用为当前地图初始化成本；本轮观察到地形和草花各重建一次。

## 早期区域检索优化

2026-10-13：用户反馈在 Godot 中按 F5/F6 后到画面出现的等待变长，且每次启动都慢。本次先测现有地图并优化区域检索，保留当前镜头、光影、植被密度、随机种子与布局。

## 主要原因

正式地图已扩为 65×77 格。`GroundDressing._region_surface()` 原先对每个草花区域遍历整张地图，检查高度、地表资格、相邻格与多边形裁切。很多格子实际位于区域之外，仍重复进行这些计算。

启动中，初始草花铺设、运行时地形数据与视觉样板调整会触发三次重建，合计调用区域计算 35 次。实测重建约 5.47 秒，其中区域计算约 5.19 秒，是主要 CPU 瓶颈。资源读取约 1 秒，背包初始化约 0.13 秒，地形重建两次合计约 0.30 秒。

这些数值包含被调用函数的耗时，嵌套函数不能重复相加。

## 已接入的优化

`scripts/world/ground_dressing.gd` 根据区域变换后的包围盒限定待检查的地形格，保留一圈边界余量，继续使用原来的精确裁切、格子遍历顺序和随机规则。因此旋转、缩放、台地、道路和地图边界的处理继续保留。

| 测量项 | 优化前 | 优化后 |
| --- | --- | --- |
| 正式地图草花重建，三次合计 | 5.47 秒 | 0.63 秒 |
| 其中区域表面计算 | 5.19 秒 | 0.39 秒 |
| 正式地图 CPU 初始化，无图形渲染对比 | 7.49 秒 | 2.82 秒 |
| 正式地图原生 D3D12 首帧 | 8.79 秒 | 5.08 秒 |

原生测试使用 Godot 4.7.2、RTX 3050、项目当前显示设置与正式地图实际启用的 Lumina 镜头。首帧计时从测试脚本开始，包含资源读取、场景实例化、初始化和首帧绘制，不包含编辑器发起调试进程的前置等待。无图形测试用于隔离 CPU 工作，不能代表真实画面出现时间。数值为本机样本，会受系统负载及缓存状态影响。

四境视觉预览地图的 CPU 初始化约 0.5 秒，原生首帧样本约 0.92 秒；当前重建瓶颈主要影响已扩大的正式地图。

## 后续可优化的顺序

1. **合并启动阶段重建**：先准备运行时地形、画笔及草花参数，再统一生成。当前仍有三次草花重建和两次地形重建；调整前需核对种植遮罩、天气和其他节点的初始化依赖。
2. **缓存或预烘焙静态内容**：保存地形网格、碰撞、草花实例及根部遮蔽结果；地形、画笔和撒布参数变化时失效并重建。运行时种植继续通过遮罩表达，保持编辑器地图独立。
3. **分开检查资源与首帧渲染**：可将较重资源放到后台加载，完整管理页按首次使用创建。后台加载仍需正确等待完成，提前取回结果会阻塞；它也不能替代减少区域计算。[Godot 后台加载说明](https://docs.godotengine.org/en/4.6/tutorials/io/background_loading.html)
4. **检查着色器与管线编译**：使用编译监视器确认首帧开销，再决定预热和导出时的 Shader Baker。Shader Baker 作用于导出包，不直接优化当前编辑器 F5/F6；图形管线仍与显卡和驱动有关。[Godot 管线编译说明](https://docs.godotengine.org/en/4.6/tutorials/performance/pipeline_compilations.html)

后续项是优化方案，本轮只接入区域检索和相应验证，没有改造加载流程或降低视觉配置。
