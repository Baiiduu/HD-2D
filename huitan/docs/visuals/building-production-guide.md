# 城市建筑制作规范

适用于 `huitan` 的新增城市建筑与已有建筑外观重做。建筑应融入现有医院、便利店及人物的视觉尺度，四周可观察的立面都应有合理设计。

**先确认三视图、风格与各面布局，再制作模型和 UV，最后一次生成整套颜色贴图。** 不通过分别生成大量墙面来试探设计，再把不一致的结果拼进图集。一次生成是生产目标，不代表模型一定一次成功；输出偏离已确认布局时，应先查明原因并修正输入，不自动扩成多轮付费尝试。

## 一、开始制作前确定范围

先从当前地图和原始资源读取实际情况，明确建筑用途、占地、朝向、层数、高低体量、人物尺度和对照建筑。用户已经确认的方向继续沿用，不重复询问。

- 地面保持同高，建筑可以高低错落，不要求楼层或屋顶高度一致。
- 以简单主体、真实转角、内凹入口、雨棚和屋顶轮廓体现体积；平面窗框、把手、卷帘纹、管线与栏杆细节优先用贴图。
- 当前咖啡馆、维修铺不做内饰和外露地基；其它建筑按具体需求确定。
- 新增建筑需要服务于战斗空间，保留宽通路、横穿和外围绕行空间。参考图确认不等于授权摆入正式地图。

## 二、设计确认材料

设计材料在一轮中交齐，便于用户整体判断。概念参考使用 GPT；生产贴图优先使用 Meowa。参考图不是最终纹理，不能代替实际立面展开。

### 三视图与完整立面

提供比例一致的正面、侧面和顶面三视图，标出朝向、宽深高、楼层分界、入口和屋顶高差。另补背面；左右不对称时，两侧分别展示。三视图不能成为省略其它面的理由。

所有图使用同一套体量与门窗位置，避免正面有门、侧面却被管道或模型封住，或者不同视图的屋顶高度互相冲突。补充一个有助于理解体积的斜视参考即可，不以单张好看的正面图代替整栋设计。

### 风格对照

使用现有建筑的真实原始贴图作为依据，同时对照人物尺度。比较主色、色阶、线条粗细、玻璃、金属、接缝、细节密度和像素尺度，不能只写“像素风”后让生成器自行理解。

维修铺当前参照便利店的炭灰墙、清晰深色细线与灰绿窗。医院可用于比较结构与尺度，但不能未经确认就混合两者的墙面色调。新建筑有自己的用途与重点，不照搬便利店整栋外观或招牌。

正式战区的存量建筑与设施统一以现有医院和原便利店为风格及完成度基准。医院的浅冷灰墙与青绿识别、便利店的炭灰墙与蓝色灯牌保留各自用途；共同统一深色细线、玻璃层次、金属接缝、设备和管线的画法。咖啡馆、维修铺及远景楼群不作为这一轮的对照或修改对象。

### 正式视角下的细节分配

按 World 当前保存的镜头工作：FOV 28°、距离 30 米、俯角 30.627°，同时考虑 Q/E 转向。正面、可见侧面和顶面均为主要展示面，必须有同档完成度；背面与另一侧也按真实功能完成，不因默认镜头暂时看不到而省略。

- 正面先保证入口、标识、门窗与功能分区清楚，细节落在完整的结构上。
- 侧面补齐窗框厚度、设备接口、检修门、通风格栅与管线转角；不重复贴正面或只留一面纯色墙。
- 顶面单独规划 UV 和像素预算。压顶、检修盖、风机或通风口、设备基脚与排水路径应有合理布局；保留大块干净表面，不用满屏螺丝、颗粒和零件制造精细度。
- 外凸雨棚、檐口、主要设备高度与真实转角用几何；接缝、格栅条、铰链和大部分细小紧固件用贴图。细节不能改变人物实际反弹面或堵住现有通路。

### 各面布局

逐面明确主要功能、门窗位置、设备与管线路径、重点和留白。下面是需要交齐的内容，不是所有建筑都必须安装的配件清单。

| 面或区域 | 需要确认的布局 |
| --- | --- |
| 正面 | 主入口、营业或维修开口、招牌、雨棚，以及视觉重点 |
| 左侧与右侧 | 窗、通风或检修位置；是否非对称，管线如何转角和落地 |
| 背面 | 后勤入口、窗、设备或合理留白；不能用重复空墙加单窗代替设计 |
| 屋顶 | 高低层关系、压顶、设备与排水；避免无用途地堆满零件 |
| 内凹与交接面 | 门洞侧壁、檐下、低屋顶上方露出的高楼墙面，以及转角连续关系 |

允许设计明确的空墙，细节不必铺满每个面；留白应与功能和构图一致，而不是漏做背面。重要标识在正式镜头距离仍应可辨认。

**用户确认以上内容后才进入生产。** 若修改体量、风格或门窗布局，应先更新对应设计图；已确认部分不反复请求确认。

## 三、白模与 UV

按确认尺寸建立主要体块，用当前人物和已有建筑做尺度对照。入口、雨棚与高低屋顶做真实几何，平面装饰不逐条拆成网格。碰撞只覆盖真实实体，保留内凹入口和可行走空间，并沿用项目的反弹与建筑遮挡接口。

UV 按**正式地图中缩放后的世界尺寸**规划。本轮以两个实物示例为准：医院当前约 80、原便利店约 75 原生像素／世界米，战区新制作面目标取约 75～80，并让正、侧、顶保持相近密度。此前维修铺使用的约 40 像素／米不是本轮统一上限，也不自动放大、重采样已有素材。上述示例密度由网格真实 UV、纹理尺寸和正式实例缩放估算，不能只看 GLB 导入尺寸或贴图总分辨率。

颜色图集优先共用一张，512×512 能装下完整设计与边距时继续使用；确有需要才按布局选择更大图集，不为塞入固定尺寸而缩小原生素材。ORM 与法线沿用同一 UV；重复部位可以共用，但不能把完整屋顶挤进纯色小格或把不对称面强行重叠。

先做适合绘制的完整立面展开，再建立它与各网格面的 UV 映射。给 Meowa 的是少量清楚的完整立面矩形，不是要求它猜测上百个碎 UV 岛的用途。转角、横向楼层带、内凹墙与分段网格使用同一坐标规则连续裁切。

UV 岛预留防串色边距，小图集可沿用维修铺的 4 像素边距并扩展边缘像素。局部重复只用于确实共用的结构，不拿同一张窗墙替代全部方向。

### 碰撞部位的材质标记

新增建筑在 `StaticBody3D` 的元数据中设置字符串 `collision_surface` 作为默认材质；混合建材在对应 `CollisionShape3D` 上覆盖。例如石底铁栏的身体默认 `stone`，石柱保留默认，铁杆形状标记 `metal`；长椅木板标记 `wood`，金属脚架标记 `metal`。同一盒子同时包住多种建材时按主要接触面标记，不能靠更换标签区分盒子的各个面；需要独立反馈的部位在建筑碰撞设计时分开建立形状，保留真实通路。

| 标记 | 当前使用 |
| --- | --- |
| `stone` | 石墙、花池、陶盆及建筑实体墙 |
| `wood` | 木箱、木桶、木板和座椅 |
| `metal` | 铁栏、路灯、金属支架与设备 |
| `fabric` | 麻袋与沙袋 |
| `water` / `mirror` / `boundary` | 水域挡块、反射镜印、地图空气边界，分别保留语义 |

程序生成建筑使用 `scripts/core/collision_surface.gd` 的 `mark(node, &"wood")`。`PlazaProp._body(label, surface)` 设置身体默认值，`_collider(body, shape, center, surface)` 设置部位覆盖；`RicochetProp._solid_box()` 在生成时按明确的建材键写入形状标记，直接调用 `_collide()` 的曲面也须传入材质。标记随每次 `build()` 重建，不依赖编辑器里临时生成的节点。

解析顺序为命中形状、碰撞身体、最近的父节点。旧 `movement_surface` 整数继续兼容，同一节点优先使用新标记。渲染合批不移动碰撞节点，不影响标记；单独更新标记不修改原生形状或导航缓存。

声音端不再判断建筑脚本类型。新增材质字符串可直接使用，再通过 `CoreFeedbackAudio.bounce_surface_cues` 配置音库事件；声音资源仍须按音效审核流程确认。尚未配置的材质使用 `default_bounce_cue`，当前为既有第一条本体反弹声，不产生新音效。详见[声音接入说明](../audio/movement-audio.md)。

新增建筑后运行 `tools/run_tests.ps1 -Test test_building_collision_surfaces`，自动实例化 `scenes/buildings/` 全部建筑并检查每个碰撞部位有有效标记；混合部位的实际建材仍需人工核对。

### 人物遮挡透明接入

独立建筑的根 `Node3D` 加入持久分组 `occlusion_buildings`，保存到建筑场景；实例继承该分组。正式地图的 `BuildingOcclusion` 会登记同一 World 节点树下的分组建筑，直接放在 World 根节点下也有效，无需给每栋建筑挂淡化脚本或修改固定名单。普通无分组道具仍只在配置的 `building_root`（World 当前为 `WorldDetails`）范围内收集，其他地图的分组建筑不受此控制器影响。

房屋沿用现有分段盒碰撞判断相机至人物的遮挡，保留门洞和凹角空区，不为淡化增加包住整栋建筑的大盒。真正挡住人物时，建筑全部子网格（包括屋顶细节与植物）一起渐淡；移出遮挡后延迟恢复。只改变实例透明度，复用原模型与材质，保留真实碰撞、灯光和阴影。主菜单与入场保持完整显示，关闭或移除控制器恢复原值。

默认每 0.5 秒刷新登记、每 0.05 秒检测玩家，不遍历怪物；运行中新增实例由现有轮询发现。淡化保留不透明度、检测间隔和过渡时间可在 `BuildingOcclusion` 或参数总览「视觉」调节。启用静态合批时沿用开始淡化退出合批、完全恢复后归还的机制，不按透明度逐帧重建。无界面回归覆盖登记范围、实际建筑部件、恢复与合批；最终观感仍需在正式地图人工验收。

## 四、一次生成整套颜色贴图

准备一张完整布局稿，把正面、左右侧、背面、屋顶、招牌和必要的内凹面按确定尺寸排好。布局稿中明确每块区域的用途、门窗位置、朝向、楼层横带和空白分隔区。

将布局稿与最相关的现有建筑贴图作为参考，**一次提交 Meowa 绘制整张生产颜色图**，统一各面色板、线条和细节密度。不能把八块区域理解为八次分别生成；也不在确认前自动批量试图。

提示只描述必要约束：按布局精修、保持尺寸和位置、参考哪种现有风格、各区域的功能，以及干净色块的要求。不能期待生成器单凭文字自动理解模型的 UV。

纹理保持清晰结构与克制色阶，不添加随机噪点、颗粒、满面斑驳或裂纹。磨损只在少量结构边缘点到为止。颜色图不绘制固定方向的强投影或强高光，主要立体受光由游戏材质和真实灯光承担。

生成后先查看实际结果，再装入图集。必须检查是否真的画出了约定的门窗与设备、是否直接复制了参考建筑、是否改变布局或留下透明孔洞。模型声称尺寸不等于输出已符合要求。

允许按实际边界裁切、排版及少量边缘补齐；保留生成素材的原生像素和透明度，不缩放、平滑或再次像素化来掩盖比例错误。关键结构位置漂移、缺面或风格不符时，修正布局或生成方式，不把错误图直接贴回模型。额外付费重试先说明问题、修改范围和可核实的费用，再由用户决定。

## 五、图集与材质

要分别说明“绘制了多少块内容”“调用了多少次生成”和“运行时用了多少张纹理”，三者不是同一个数字。

| 内容 | 当前默认做法 |
| --- | --- |
| 颜色图集 Albedo | 一张，容纳整栋各面的颜色与平面细节 |
| ORM 合图 | 一张，R 为环境遮蔽 AO、G 为粗糙度、B 为金属度；与颜色图共用 UV |
| 法线图 | 按实际需要决定，不默认增加 |
| 材质 | 优先共用一个，避免按门窗、管线、屋顶逐件拆材质 |

ORM 是表面属性图，不需要让 Meowa 再绘制一套彩色立面。按确认的材质区域生成属性；没有可靠遮蔽信息时 AO 保持中性，不用深色 AO 把建筑整体压黑。确认引擎实际通道设置与贴图含义一致。

原生像素使用最近邻采样与无损导入，不启用会破坏细节的有损压缩；是否使用 mipmap 应按项目显示要求明确选择并检查串色。维修铺当前关闭 mipmap。图集边距与材质设置一起验证。

## 六、核验与交付

先检查资源与数据：图集尺寸、区域边界、UV 对齐、边距、透明度、导入设置、材质共用，以及模型和碰撞是否被意外改变。此类检查可以无界面运行。

视觉验收由用户在实际镜头下进行，自动数据检查不能证明风格合适。沿用正式地图当前镜头参数，在检查场景中与已有建筑、人物并排比较，近看细节并旋转检查所有方向；不自动启动渲染窗口或截图。

人工检查重点：各面是否完整且合理、转角是否接得上、高低层是否清楚、正式距离是否过碎或模糊、入口是否可信，以及建筑是否融入当前场景。通过后，按用户授权接入正式地图，保留原有地表、碰撞与玩法规则。

交付包含模型或场景、实际使用的颜色与 ORM 图集、材质、UV 与布局映射，以及人工检查入口。生产源图随模型放在 `source/`，以 `.gdignore` 排除运行时导入；中间脚本、下载和临时检查图放在 `D:\.codexfile\work\<任务名>`。

## 七、积分与调用约束

生产前核对当前工具、参考图数量、去背景与其它附加项的报价。先确认设计再付费生成；已知不适合的路径不重复批量尝试。任务超时或结果回传不完整时，按原任务编号恢复，不重新提交同一付费任务。

用户询问成本时，说明本次实际调用数量，区分最终采用、弃用和返工；有逐笔扣费证据才报告准确积分。共享账户余额变化不能直接当作本次费用，工具未返回准确扣费时明确说明无法核实。裁切、UV 排版、合图和本地生成 ORM 不消耗 Meowa 积分。

沿用项目“暂停新增调用日志与同步页面”的约束，不另建调用流水；成本核对使用已有任务回执和可用的官方扣费信息。

## 八、战区存量统一的执行范围

当前盘点为正式 `WorldDetails/BattleCourts` 及战区边沿设施。中央地标采用已确认的精简赛博朋克球体；花坛采用已确认的无灯城市槽体，复用原组件与实例。两者正式地图观感仍待人工验收。保留地图位置、既有占地区域、通路与建筑遮挡接口，让可见实体和真实碰撞对应，不用旧碰撞包住新设计的留空处。

| 对象 | 当前实例 | 本轮处理 |
| --- | --- | --- |
| 医院、原便利店 | 2、3 | 风格与原生像素密度基准，保留已有外观 |
| 便利店变体 | 2 | 用户确认保留当前效果，不纳入本轮修改 |
| 市政设备模块 | 1 | 用户确认当前效果可以，保留现有模型、贴图与布局，不纳入本轮重做 |
| 中央环球雕塑 | 1 | 采用精简赛博朋克独立静态场景，保留原位置与占地，去掉花草，正式地图人工验收 |
| 花坛 | 2 | 本轮重点：以模块化种植设施重设计槽体、转角和压顶；取消附灯及其光效，保留原有木坐面、树木、花草和占地区域 |
| 长椅、桶组、单桶 | 2、1、1 | 用户确认保留现状，不纳入本轮修改 |
| 垃圾桶、木箱排 | 1、1 | 后续沿同一材质画法核对，不自动扩成整批造型重做 |
| 独立路灯、战区外围铁艺栅栏 | 3、36 段 | 保留现状；不随本轮设施设计扩改灯位、照明或外围排布 |

花坛已按无灯参考接入城市面板与压顶，沿用原位置、树木花草、木坐面及占地；原石砌素材与可选附灯保留兼容。医院、便利店及其变体、市政设备、独立长椅和木桶保留当前效果；咖啡馆、维修铺、远景背景图与三维远景不纳入此轮，不借统一风格更改战斗地图结构。

| 设施 | 各面布局与细节方向 | 保留内容 |
| --- | --- | --- |

### 中央赛博朋克球体资源

球面着色器 `shaders/environment/cyber_armillary_globe.gdshader` 将原网格 UV 矩形还原为完整展开坐标，网格、原 UV、碰撞及正式地图变换均保留。`longitude_offset` 使主要图案朝向当前正式镜头，经度交接处以窄幅双边混合柔化原画边缘，两极采样图中深色留白；`seam_width` 和 `emission_energy` 可在球面材质调整。

`AuroraMotion` 使用引擎 `AnimationPlayer`，20 秒内循环一个 0～TAU 的 `motion_phase`，极光作小幅连续变形，并由宽缓的明暗波沿极光带推进，交代正式镜头下的流向；不滚动整张颜色图。星点按固定的各自相位轻微闪烁，新月和星座细线保持稳定。`flow_strength` 默认 0.018、上限 0.02；`flow_light_strength` 默认 0.4，按安全流动遮罩调节明暗波，颜色变化量为发光的 45%，设为 0 仅保留形变。金色图案周围 22 原生像素从流动中排除，避免采到邻近星点形成重影；`twinkle_strength` 默认 0.1，发光约 ±10%、颜色约 ±2.5%，`twinkle_cycles` 默认 5，即每次大循环闪烁五次。播放器的 `speed_scale` 调整整体速度。两极和经度接缝附近收住形变，循环采用整数相位避免回卷跳变。

动画只推进一个材质参数，不增加图、网格、透明层、粒子、光源或渲染视口，流动区域额外采样同两张图。材质按场景实例独立、图和 shader 共用；`aurora_globe_motion.gd` 只在入树后沿父级寻找当前地图的 `WavePrototype` 并登记播放器到既有冻结机制，没有脚本逐帧回调。冻结保持当前相位，恢复不补算暂停时间，退出自动撤销登记；独立预览无波次时照常播放。`test_cyber_armillary_motion` 无界面验证这些时钟行为，实际流速、可读性与 GPU 帧耗仍由正式地图人工验收。

共用 512 图集的 ORM 保持标准 RGB 含义，**alpha 额外存发光遮罩，不是透明度**。底盘大面按 `source/approved_top_reference.png` 改为哑光钛灰金属面板，粗糙度约 0.65、金属度约 0.75，收住整片平板的镜面反光；窄包边与外沿保留较清晰的金属高光，不能恢复成零金属度的石材。共享着色器 `shaders/environment/cyber_armillary.gdshader` 使用真实光照和不透明深度，支持面板顶点色作轻微明度区分，材质的 `emission_energy` 可调；不新增光源、粒子或逐帧节点逻辑。两张图无损导入，着色器最近邻采样，ORM 导入关闭透明边缘修复，避免其 RGB 属性被发光遮罩影响。

顶面围绕原支座分成八块宽大的切角扇区，每块具有真实浅凹大面、窄金属包边和两枚齐平紧固点，拼缝连贯，外围保留窄八边形框。结构集中在单个静态网格 `Model/DeckDetails`，替换此前的线槽、检修盖与附加安装圈；原支座与青蓝细环保留。大面采样原 Meowa 图集中无接缝的干净色区 `deck_face`，以顶点色作克制色阶变化，不改颜色图原像素，不额外生成贴图；原顶盖只改为拼缝下方的暗底，不扩大占地或修改基座碰撞。
